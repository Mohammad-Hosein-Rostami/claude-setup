# disk-free/lib

Code of `../disk-clean.mjs` (see `../README.md`).

- `clean-scan.mjs`: read-only helpers that never follow a symlink and read folders with `opendir` (`entriesOf`, `walkTree`, `treeBytes`, `touchedSince`, `mtimeOf`), and `holdsGitWork` (a worktree, changes or local-only commits anywhere in a folder; read-only git calls with the board's `GIT_SAFETY` flags).
- `safe-remove.mjs`: which roots and folders are safe (owner, mode, links) and the removal itself (`inspectRoot`, `ownedFolder`, `removeInside`, `moveAside`, `moveBack`, `isOwnAside`); the header says what it does and does not defend against.
- `lock-file.mjs`: the lock file of the start hook and of `--apply` (`takeLock`, `releaseLock`); a stale lock is broken by one process only.
- `live-sessions.mjs`: ids of the sessions whose process is alive, from `~/.claude/sessions/*.json`.
- `first-seen.mjs`: when disk-clean first saw each scratchpad cs-test or clone folder (`openFirstSeen`, `recordKey`), one JSON file through `hooks/lib/session-store.mjs` under `hooks/lib/session-lock.mjs`; entries of gone folders are dropped.
- `clean-rules.mjs`: the six rules, each an async generator that yields what to remove and how to check it again (`rulesFor`, `AGE`). Change an age limit in `AGE`.
- `job-made.mjs`: the job-made record, what a job of this setup made and may leave behind (a lane folder, an artefact folder, a download, a log, a screenshot, a docker container, volume or image), so the job-leftover sweep can remove only recorded or marked things, never by size alone (the sweep and the writers in `git-tidy lane` come in later changes; nothing reads or writes the record yet). One append-only file per session, `~/.claude/state/job-made/<session>.jsonl`, one JSON line per `made` or `gone` event (`recordJobMade`); `readJobMade` reads every session (torn and newer-version lines skipped and counted, `stale` after 30 days without a new line) and `stillMade` gives what the newest events say is still there (within one session the later line wins even if the clock stepped back; across sessions the newer time, a tie counting as gone). A record file with a second hard link is neither written nor read. Path keys must be absolute with no `..` part and are stored without `.` parts, doubled or trailing separators, so two spellings of one folder are one key. Each file is capped at 1 MiB for writer and reader alike: the first record that does not fit writes one `full` line, later ones are refused, nothing is cut. The writer never deletes a record; dropping stale ones is the sweep's job. Keys are stored only as JSON strings and never handed to a shell.
- `test-temp-prefixes.mjs`: the name prefixes the tests used before `tests/temp-dir-helpers.mjs`; a fixed list, it does not grow.

Tests: `tests/disk-clean*.test.mjs` and `tests/job-made.test.mjs`, for example `node --test tests/disk-clean.test.mjs` (fake roots only; the real folders are never touched).
