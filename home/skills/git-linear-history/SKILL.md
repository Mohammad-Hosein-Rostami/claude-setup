---
name: git-linear-history
description: Use when integrating a branch, pulling or landing lanes, or when the owner asks to clean up git (merge commits, tangled or leftover branches, old worktrees). History stays one line - rebase, never merge.
---

Goal: `git log --graph` of the base branch is one line of small Conventional Commits, and no branch or worktree outlives its work (C37).

**Every day**
1. Start from the up-to-date base: `git switch -c <type>/<what-it-does> <base>` (a name from the work, e.g. `fix/accounts-keychain-patch`, never a chain id; tags only by owner order). Commits: subject <= 60 chars, body with what and why. Parallel lanes each get their own worktree and branch; in claude-setup `scripts/lane-new.sh <name> [base]` makes both and runs `npm ci` for the tools.
2. Bring in the base with `git rebase <base>` (or `git pull --rebase`), never `git merge <base>` and never a merge from a sibling lane. A lane that needs another lane's work waits until that lane has landed, then rebases.
3. Land with `git switch <base> && git merge --ff-only <branch>`. If it refuses, rebase again; never drop `--ff-only`. Never land with `git update-ref refs/heads/<base>` (or `update-ref --stdin`), `git branch -f`, `git push|fetch . a:<base>` or `git fetch -u <repo> a:<base>`: they move the branch but leave the folder where it is checked out on the old files, so it shows every landed change as staged (`git-tidy check` reports `stale-checkout`; git refuses `branch -f` and a plain `fetch|push .` only when the branch is checked out in some worktree). Never commit or stash those staged changes, which reverts the landed work: sync with `git -C <folder> reset --soft <old> && git -C <folder> merge --ff-only <new>`; from a lane, land with `git -C <base folder> merge --ff-only <branch>`. Lanes land one at a time: land, then rebase the next.
3b. Land a lane with `node ~/.claude/tools/land/land.mjs <branch> [--repo <path>] [--test "<command>"]` (`--repo` is the base checkout, the folder where the base branch is checked out; default the current folder). It refuses a dirty base checkout or lane worktree, rebases the branch onto the base (a conflict is aborted, so nothing changes: rebase by hand, then land again), runs the `--test` command in the lane worktree at the rebased tip (a failure leaves the base unmoved and prints the last 40 lines), fast-forwards the base with `git merge --ff-only` to the sha it tested, then deletes the branch and its worktree (unlocking a locked worktree first). When the base and the lane changed the same files since the lane branched, it lists them and lands only with a test (`--test`, else the lane's `npm test` script). It runs no review and never pushes. Its README lists the errors.
3c. A re-done or fixed lane continues the same branch, never `<lane>-2`, `-fix`, `-fixes`, `-v2` or `-redo` copies: see "Start" in `agents/dev.md`. At session start `git-tidy-gate.mjs` names the lanes that are not landed yet; `git-tidy check` names older copies and agent leftover branches, and `git-tidy prune --apply --include-recent` removes them.
4. Right after landing: `node ~/.claude/tools/git-tidy/git-tidy.mjs prune` lists the branches and worktrees whose work is fully on the base; add `--apply` to remove them. It keeps a dirty worktree, a worktree with ignored files that exist only there, a branch with work of its own, and anything used in the last hour (add `--include-recent` for lanes you landed yourself; a lane with no commit yet stays protected for an hour even with `--include-recent`). Name the base with `--base` when the repo has more than one of main, master, develop.
5. Rewrite only your own unpublished commits (no interactive rebase here: `git commit --fixup <hash>` then `git rebase --autosquash <base>`, or `git reset --soft` and recommit). Commits already on a shared remote branch are never rewritten without the owner's yes. A feature branch you pushed is updated with `--force-with-lease`, never `--force`.

**Cleaning an existing tangle** (merge commits, branches merged into each other, leftovers)
1. Stop feature work; every worktree clean; list worktrees, local and remote branches.
2. Back up first: `git bundle create <path outside the repo> --all`, checked with `git bundle verify` and `git bundle list-heads` (every tip listed). The bundle is the backup that stays until the owner releases it. Tags `backup/<date>/<branch>` on the tips are a working aid only: they keep the old lines visible in the graph, so they are deleted in step 8.
3. Inventory each branch against the base (`git log --oneline --no-merges <base>..<branch>`, `git cherry -v <base> <branch>`) in a table in the report: commits not on the base, verdict (needed / contained elsewhere / obsolete), proof. Work that exists nowhere else is integrated or listed for the owner, never dropped on a guess.
4. Build the state that holds all needed work; note its tree (`git rev-parse <tip>^{tree}`). That tree is the reference.
5. Linearise on a new branch from the base: replay the real commits without the merge commits (`git rebase <base>` from the integrated tip), resolving conflicts as the merges did. Keep commits small; ask the owner before squashing a stretch that will not replay.
6. Proof, quoted in the report: `git diff <reference> <new tip>` is empty; `git log --merges <base>..<new tip>` is empty; `git-tidy check` is clean on the new tip.
7. Fast-forward the base to the new tip. If published history on the base would have to change: stop and ask the owner. When the base has an upstream, `git fetch` first and `git pull --rebase` when the upstream holds commits the base lacks. A published commit is never amended, rebased or pruned without the owner's yes (C37): fixes go on top. The setup never pushes.
8. Remove everything that still reaches the old tangle: `git-tidy prune --apply` for merged branches and worktrees, then delete the `backup/` tags and the temporary branches by hand (the bundle holds the old history) and run `git fetch --prune`. The owner confirms each remote step (push, remote branch delete, force-with-lease). Leave stashes and anything you cannot account for; list them.

Done-gate: `node ~/.claude/tools/git-tidy/git-tidy.mjs check` exits 0 and prints `all local refs on one line: yes`: no unpublished merge commit is reachable from any local branch or tag and no merged branch, worktree or backup tag is left, so `git log --graph --all` shows one line (merge commits teammates already published stay; say how many). Report: branches removed, branches kept and why, backup tags removed and bundle path, the proofs.
