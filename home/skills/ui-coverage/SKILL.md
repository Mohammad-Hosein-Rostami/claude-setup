---
name: ui-coverage
description: Use for any UI task with more than one component, any Figma or pixel-perfect work, any "all screens / all forms / everywhere" request, and any i18n or RTL work - build a coverage matrix of surfaces x states x locales, gate it with ui-coverage check, hand over a live page.
---

Rules: U13, U14, U1, U2. Tool: `node ~/.claude/tools/ui-coverage/ui-coverage.mjs <init|expand|scaffold|check|states>` (README beside it has the matrix.json format; `init matrix.json --locales en:ltr,fa:rtl --widths 320,768,1280 --surfaces a,b` writes the skeleton). The matrix is one file per task; done = `check` exits 0.

1. **Surfaces.** Design frames + app routes + HIDDEN UI: grep the backend and sibling repos for templates (email, mjml, hbs, ejs, pug, jinja, tmpl, html strings, PDF, notifications, server error / redirect / consent pages). Record each search command and its hit count in `searched` (proof it ran, even at 0 hits). Hidden surfaces are RENDERED, not only listed: render templates (email, server pages) with sample variables per locale to static HTML and serve them, or run the project's server; each is a surface in the matrix with its own cells. A frame with no code home is built, listed with a reason, or asked about once; never defaulted.
2. **Controls and reuse.** For each control class (select, checkbox, radio, switch, text field, phone, button, dialog, toast...) find the existing component in the project's design system and in sibling apps/zones; record its path in `component` and, in `mountedAt` (`<file>:<line>`: the line that instantiates or places this control, one line per control); `check` fails with `unproven-reuse` when that file or line is missing or the component (its file name, or `componentMarker`) is not mentioned within 5 lines of it. A control that does not import or instantiate the design-system component is `new` (with a reason the owner would accept; it still needs `mountedAt`) or a fail; writing the component path does not make it reuse (U14).
3. **States per control.** Each control has a known `class` (or `other` with its states listed by hand; a misspelled class is an error). The default states per class are listed once, in the tool: run `node ~/.claude/tools/ui-coverage/ui-coverage.mjs states`. Cover them all, or drop one in `dropped` with a reason. Every OPEN state (option list, menu, autocomplete, picker, tooltip, toast, validation text) is checked for translation in every locale, and the source of its labels is named (constants, API, i18n file). A state the harness cannot render is a gap to list (`deferred` + reason), not a skip.
4. **Locales and direction.** Read the supported locales from the i18n config; every one is in `locales`. The matrix `tag` is the locale code the app itself uses (the config key may be `code`, `locale` or `lang`), and `ui-check batch` states use the same string. RTL (U13): logical CSS properties; only the typed VALUE of phone, email, URL, code, number and card fields is left-to-right, and only while the field holds a value (e.g. `input:not(:placeholder-shown) { direction: ltr }`); the placeholder is translated text and follows the page direction and alignment like label, hint and error (`dir="ltr"` on the input is right only when it has no translated placeholder); check both states, empty and filled, in every RTL locale. List every value on each surface that stays left-to-right (typed or shown: phone, email, URL, handle, password, OTP, card, IBAN, postal code, Latin-digit numbers, IP, path, version, code samples, Latin brand names; shown ones isolated with `<bdi dir="ltr">`) and what is never mirrored (logos, media controls, clocks, numeric-axis charts, keypads, check marks); unsure whether a value follows the language: ask. Directional icons mirror; long strings do not clip; a font per script.
5. **Reference behaviour.** When the same fields exist in a reference app or API, read its validators first and match them; put the path in `reference`, or `none: <reason>`; `none:` is accepted only when `searched.reference` lists the search commands with hit counts. Every input control has an `error` state reached by submitting a value the reference rejects (not only an empty value), and its evidence shows the message.
6. **Gate.** `expand matrix.json` (a cell for every state x locale x width), then scaffold, fill url and steps, `ui-check batch --jobs N`, check: `scaffold matrix.json --out states.json` writes the `ui-check batch` states skeleton (one entry per open cell, with the matrix's own surface, state, locale and widths; never type those names by hand), you fill `url`, `steps` and `defaults`, `ui-check batch --states states.json` writes results.json, then `check matrix.json --results results.json`. A record whose width, locale, surface or state is not in the matrix stays an error, and its message says what to change (a Figma compare record carries the frame width, so add that width to `widths`). Fix and re-run until it exits 0. `check` prints the verdict first, then problems grouped by root cause (`--verbose` lists every cell). When you observe a fault the tools cannot detect, hand-set that cell to `fail` with a reason; the report lists hand-set cells separately. Rules the tool enforces: every state at every width and locale (`stateWidths` + `stateWidthsReason` may narrow control states); a `fail` from any source wins, also over na/deferred, and a pass never clears it; `na` in a non-base locale (the first in `locales`) only where the base locale is `na` too, else pass or `deferred`; evidence is a URL or an existing file (relative to the matrix); every reason has 15+ characters. After a batch, read the hints in summary.md: each is confirmed (hand-set the cell to fail with a reason) or dismissed in the report with a reason.
7. **Deliverable.** For a review-only task `deliverable.reviewUrl` is the served pages; for a build task it is a live review page (served route or static HTML built from the real components, with state and locale switches), never screenshots alone. Dev-only mocks and showcases are proven absent from the production build: build, grep the output, quote the result in `deliverable.mockExcluded`.
8. **Report to the owner.** Paste the tool summary, including every `na` and `deferred` cell with its reason.
9. **Timed-out question.** A scope or component question that gets no answer: take the option that keeps the full scope and reuses the existing component; log it as taken by default.

Done-gate: `ui-coverage check` exits 0 (summary pasted); live page URL given; mock-exclusion output quoted; then `ui-quality-pass` and `verify-done`.
