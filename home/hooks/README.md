# home/hooks

Claude Code hooks installed to `~/.claude/hooks` (a symlink to this folder). All are Node 22 scripts with no dependencies.

- `session-notes.mjs` - SessionStart, UserPromptSubmit: prints the lead rules (`~/.claude/lead-rules.md`; nothing when the file is missing) at SessionStart (the project-agents line is in the `project-merge.mjs` note); on a compaction adds the compact notes; on a prompt, the once-per-session big-context line. Inside a subagent (`agent_id` in the SessionStart input) it prints only a one-line compaction note (re-read the brief and the Standing rules of the STATUS file it names; no STATUS path from the transcript, which is the lead's there). One 4 s deadline below the hook timeout covers the prune of its state files (`lib/state-files.mjs`); the project-agents child (`lib/project-agents-timed.mjs`) runs under the `project-merge.mjs` deadline.
- `lead-text.mjs` - SessionStart (every source): prints the lead text (`~/.claude/lead.md`, without its `<!-- -->` editor notes) to the main session as a hook string of its own, so it has its own 10,000-character room next to the one `session-notes.mjs` prints. Nothing inside a subagent or when the file is missing; never blocks.
- `project-merge.mjs` - SessionStart (startup, resume, clear, compact; the lead only) and SubagentStart: says what the project's own AI setup brings beside ours (CLAUDE.md, AGENTS.md and whether it loads, `.claude/rules`, skills with the ones ours hide by name and their paths, agents with `maxTurns`, hooks, settings that change ours, MCP servers), warns when the project turns all hooks off (`disableAllHooks`) or may hide our CLAUDE.md (`claudeMdExcludes`), and adds the project's note found by its repo key (`home/project-notes/<key>.md`, then `~/.claude/project-notes/<key>.md`; a note `CLAUDE.local.md` imports by that very file is named, not repeated). A worker gets the hidden skills and the notes. Its own hook string (JSON `additionalContext`), at most 6,000 characters for the lead and 4,000 for a worker; repository names and values are labelled as data and quoted; read-only, no state; one 4 s deadline below the 5 s timeout. Prints nothing for a project with no AI files and no note, in HOME, or for a SessionStart inside a subagent.
- `skill-router.mjs` - UserPromptSubmit, PostToolUse(Edit|Write|MultiEdit): names the skills to invoke for the prompt or UI file; a bug/fix intent names `root-cause-debug`, a repository restructure `repo-restructure`, git history or branch work `git-linear-history` (each once per session); a repeated report ("still wrong", "i told you before") shows a line that names no skill on every match. The gate routes are in `lib/gate-routes.mjs`. Routes only the owner's own words: cross-session messages, task notifications and system reminders are cut out first. Off with `CLAUDE_SKILL_ROUTER=off`. Never blocks.
- `pre-bash-guard.mjs` - PreToolUse(Bash): never blocks for good. A command with a hit that a rewrite fixes (a variable command word, a risky word inside shell expansion, a literal secret) is first bounced back once with the fix (`lib/bounce-once.mjs`), and the bounce names every other reason that will still ask after the rewrite; the identical command sent again gets the dialog (without a GUI, the CLI's ask). Quality rules (a hand-edited lockfile, a `git merge` or `git pull` that can make a merge commit, a branch moved by `update-ref` (a literal branch or HEAD, a ref in a variable, `--stdin` text setting anything but a literal ref outside refs/heads/), `branch -f`, `push|fetch .` or `fetch -u <repo>` instead of `merge --ff-only`: `lib/branch-move.mjs`; git itself refuses `branch -f` and a plain `fetch|push .` onto a branch checked out in any worktree, the advice stays for the rest; a copy of an existing lane branch (`checkout -b x-2` while `x` exists): `lib/git-advice.mjs`, which asks git under one 2 s budget; a wait by sleeping, a `for|while|until` loop that sleeps 5 s or more or one `sleep` of 30 s or more, unless the call is sent with `run_in_background: true`: `lib/wait-advice.mjs`) are advice, never a dialog: the first send comes back with the fix and the identical command sent again runs. Rules (--no-verify, force push, rm -r outside the project, rm -r of a whole folder inside it (the working directory itself, or a bare glob such as `*`, `./*`, `.*`, `./**/*` of the working directory, the project root, home, a temp root or `/`: `rm -rf *` asks, `rm -rf src/*` and `rm -rf *.log` do not) or run by xargs/parallel (also in their `sh -c` script), disk wipes, literal secrets, printing a keychain secret or `gh auth token`, `gh ssh-key add` of a non-`.pub` file, a credential file or folder next to a network sender, cloud upload or ssh stdin, push, gh release/pr merge, publish, prod-host writes) open a timed dialog: Allow by default, no answer in 2 min (max 190) goes ahead, Deny on click, native ask when there is no GUI or the dialog failed. Allow and timeout print no decision, so the normal permission flow and deny rules still apply. Commands inside a command get the same rules, their reasons joined to the outer command's (deeper than 24 levels asks): `bash -c`, `eval` and `$(...)` bodies, and every command git itself runs (`lib/git-runs.mjs`). Git's own programs (`git-push`, `<exec path>/git-rebase`) count as `git <sub>`, a `git config` value is read also when it is dashed or follows `--`, and the value of a variable git runs (`GIT_EDITOR`, `GIT_PAGER`, `GIT_SSH_COMMAND` ...) is checked wherever the line assigns it, with git after it or not (`lib/git-run-values.mjs`; a value it cannot read asks "git runs a command this guard cannot read" unless it is one reference such as `"$EDITOR"`). Command words are folded the way macOS and Windows match names (`GIT push`, `/BIN/RM`, `ſh` is sh); a command word still outside ASCII after that asks next to a dangerous word. Git-run variable names ignore case on Windows (`git_editor`), and are exact elsewhere. `NAME+=x` and `NAME[i]=x` in front of a command are assignments; unquoted brace words are expanded as bash does (`rm {-rf,x}`), and one the guard cannot list asks in a command it checks; an unquoted variable whose value has blanks is judged as each word bash splits it into. Logs decisions and `sed -i`/heredoc code writes (for the typecheck gate). It never fails open on its own errors: a failure in its code after the rules asks ("guard error: <error class>", logged as `guard-error`), and `"onFailure": "block"` on its entry in `settings/base.json` blocks the call when the hook dies or times out.
- `question-answered.mjs` - PostToolUse(AskUserQuestion): writes the mark (`~/.claude/state/question-answered/<session>.json`, sha256 of agent and question texts, 0700 folder and 0600 file, links refused, dropped after 15 min) that tells `permission-timed-allow.mjs` the owner answered in the terminal, so its popup closes. A mark older than the popup never closes it. Prints nothing, always exits 0.
- `notify.mjs` - Notification(permission_prompt, elicitation_*, quota_auto_resume_stale|disabled), StopFailure(rate_limit), Stop: the desktop notes of display design 7.10 (needs you, with the question's short header, limit stopped work, the queued agent-failed note) as `terminalSequence`, on the owner's `preferredNotifChannel`.
- `artifact-ask.mjs` - PreToolUse(Artifact): the same timed dialog before an Artifact publish or delete.
- `permission-timed-allow.mjs` - PermissionRequest(`*`): every Claude Code permission prompt (any tool incl. MCP tools, Agent and ExitPlanMode plan approval (its allow echoes `updatedInput`), protected-file writes, ask rules; any permission mode; interactive, background agents and `claude -p`, where Claude Code runs this hook too) gets the timed dialog with a 2 min wait (`CLAUDE_PERMISSION_TIMEOUT_S`, max 190): no answer or Allow allows, Deny (Esc on macOS) denies; no GUI prints nothing (the normal prompt, or Claude Code's deny where nobody can be asked). AskUserQuestion gets one dialog per question, one after the other (`lib/question-reply.mjs`; "Use recommended" is the default (Enter) button of question 1 only; questions 2..N default to "Answer in terminal" so an Enter typed in the terminal question cannot answer, and "Use recommended" stays clickable; title "question 2 of 3"), each with its own 2 min wait, showing that question (its header inside the masked, cut value) and on its own `Answer:` line the start of the option to be taken; no answer in that question's 2 min or "Use recommended" takes its "(Recommended)" option, else its first (multiSelect gets that one option), and after the last question the hook allows with `updatedInput` = the input plus `answers`; on a timeout only, `annotations` adds to that question's answer the note "No answer in 2 min: this option was taken by default, not chosen by the owner (UNCONFIRMED)", which Claude Code shows Claude in the tool result; "Answer in terminal" (Esc on macOS), no GUI or a failed dialog on any question print nothing (Claude Code's own question UI, which shows every question; never an invented answer). When the owner answers in the terminal the open popup closes within 0.25 s and no later one opens: Claude Code runs this hook beside its own question and tells it nothing, so `question-answered.mjs` (PostToolUse(AskUserQuestion)) leaves a mark that the popup loop polls. Claude Code stopping the hook (SIGTERM, SIGINT, SIGHUP) also closes the open popup. The hook timeout in `settings/base.json` is 800 s: 4 questions at most 190 s each. The dialog labels the target (`Command:`, `File:`, `Path:`, `URL:`, `Query:`, `Plan:`, `Input:`) and says what the tool asks to do in which mode; for Bash it runs the guard's rules and for Artifact the Artifact hook's, and shows that hook's own reason (e.g. the guard's DESTRUCTIVE reason, or Artifact publish / delete) when they ask. An `Input:` (MCP and other JSON input) has every secret-named field (`password`, `apiKey`, `X-Api-Key`, `Authorization`, at any depth) masked in the dialog and the log. A Bash command the guard's dialog allowed moments before is allowed with no second dialog (`lib/answered-commands.mjs`), unless the guard classes it as DESTRUCTIVE: that one always gets the dialog.
- `agent-model-guard.mjs` - PreToolUse(Agent|Task): sets `model: sonnet` on a general-purpose / Explore / built-in call that has none (general-purpose pins no model, so it would get `CLAUDE_CODE_SUBAGENT_MODEL`, or the lead model when that is unset; Explore and Plan say `model: inherit`, which skips that variable, so they would run on the lead model); Plan gets `opus`. Forks are untouched; a repo agent's file `model` and `effort` are a floor: a lower per-call value is left out (`lib/agent-pins.mjs`). A `ui-implementer` or `visual-qa` call whose prompt has no line `MATRIX: <path>` naming a coverage matrix (or `MATRIX: none: <reason>`, 15+ characters) is denied once with the `ui-coverage init` advice; the identical call sent again runs (`adviceOnce`, never the owner; any failure lets the call run). Every brief that does not name `STATUS.md` gets one first line pointing at the project's STATUS.md (inside git only the one in the nearest folder holding `.git`, when that repository's own `.git/info/exclude` lists it; a `.gitignore` or global excludes file does not count) when its `## Standing rules` section has content, and an `architect` or `Plan` brief without "Reuse inventory" gets one last line asking for the Reuse inventory and Contract facts lists (`lib/agent-brief.mjs`: fixed text and a path only). Writer isolation gate: a writing agent (implementer, ui-implementer, general-purpose or no type, claude, or an agent file whose `tools:` names Write/Edit; never scout, runner, Explore, Plan, architect) launched while another writing agent of the session still runs must carry `isolation: "worktree"`, else it is denied once with that advice and the identical call sent again runs (`adviceOnce`). Agent cap: every Agent or Task call that passes the gates is recorded, and with 5 agents of any kind running in the session (`MAX_RUNNING_AGENTS`) the next one is denied every time, also when sent again, with the text `agent cap: 5 agents of this session run (<type> <id8>, ...); wait for one to return (store: <path>)`; a launch record that cannot be read or stays locked denies too, naming the file. Running = the launches this hook let start, marked started and ended by `agent-budget.mjs` on SubagentStart and SubagentStop, plus a stopped agent that makes a tool call again (`lib/agent-launches.mjs`, `~/.claude/state/agent-writers/<session>.json`; the folder name is historic). Limits: a stop another gate blocks counts as the finish; a launch that never started counts for 2 min and an agent with no SubagentStop for 30 min after its last tool call; whether an Agent call inside a subagent fires this hook is not probed (the env `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`, the same number, is the backstop). Copy-branch brief gate, run first (`lib/copy-branch-brief.mjs`; it denies an identical call once, `adviceOnce`): a writer brief that creates a copy of an existing branch (`<lane>-2`, `-fix`, `-v2`, `-redo`) or says "new branch off <existing>" is sent back with the same-branch steps (the brief is read up to 32 KB, in linear time: the hook has a 5 s timeout).
- `post-edit.mjs` - PostToolUse(Edit|Write|MultiEdit): runs the project's own `format` script on the edited file (`CLAUDE_POST_EDIT_SKIP=all|format` skips it, but not when only the project's committed `.claude/settings.json` sets it: then it runs and warns once per session, `lib/team-switch.mjs`). It runs no lint and no typecheck.
- `commit-gate.mjs` - Stop, SubagentStop, PostToolUse(Edit, Write, MultiEdit, NotebookEdit): records each file the session or an agent changes with those tools (`lib/own-edits.mjs`, `~/.claude/state/commit-gate/edits/<session>.json`) and blocks a stop once per dirty state (agent + worktree + hash of the recorded files' `git status --porcelain` entries) when recorded files are still uncommitted, non-ignored files in the session's own worktree (a subagent counts its own files, the lead every file of the session; another session's or agent's dirt in the same folder never blocks; files a Bash command changes are unknowable and never count), asking for small Conventional Commits or a reason they stay; in the base folder (main, master, develop) with lane worktrees present it adds that edits belong in a lane. The gated worktree is the one holding `CLAUDE_PROJECT_DIR` for the main session and the one a subagent started in (first `cwd` of its transcript), never a folder the session only cd'd into. git there runs with `core.fsmonitor=false`, `safe.bareRepository=explicit` and an empty `core.hooksPath`, and a repo whose own config (includes followed) defines a filter is passed, so no program the repository names ever runs. A branch moved under its folder (index = an earlier reflog position) gets `git -C <dir> reset --soft <old> && git -C <dir> merge --ff-only <new>` instead of "commit them". Read-only agents (Explore, Plan, an agent file whose `tools:` has no Write/Edit) pass. A continued stop (`stop_hook_active`) is checked too, at most 2 blocks in a row. Passes outside git, during a rebase, merge, cherry-pick or revert, for ignored and `.git/info/exclude` files, and on the same state's second stop; any error exits 0. State: `~/.claude/state/commit-gate/<session>.json`.
- `done-check.mjs` - Stop, SubagentStop: runs `tools/done-check` on the code the stopping agent changed (project type check, lint of changed lines, related tests, weakened-test scan, failures compared with the base) and shows its one `checks:` line. Blocks once per state with the new failures, at most twice in a row; `not run`, a crash or a timeout never block. `DONE_CHECK_SKIP=all|types,lint,tests` skips it, unless only the project's committed `.claude/settings.json` sets it: then the checks run and the line says the team switch was ignored (`lib/team-switch.mjs`). No model tokens when green.
- `ask-gate.mjs` - Stop: blocks once when the lead ends with a request for the owner's decision (narrow phrases or a heading, a `D1:`/`D2:`/`D3:` list; negated, quoted and code text never match) and has not called AskUserQuestion since the last real prompt. Never blocks twice in a row (`stop_hook_active`); any error exits 0. `ASK_GATE_LOG=<file>` appends one JSON line per run.
- `agent-budget.mjs` - PostToolUse (all tools), PreToolUse(Bash), SubagentStop: a subagent gets "commit what is green" once at 80 tool calls (the first call that sees 80 or more; a marker file keeps it to one) and "commit, then return your status report" at 120 (again every 10 calls), advisory only; a Read over ~20k chars in the lead session gets a "use scout" warning; the lead gets a "delegate the rest" line stating the context size (from the transcript's last usage) every 15 Bash calls with no Agent/Task call between (an Agent/Task call resets it); a nudge followed by another Bash call counts as ignored, and after 2 ignored nudges, at 150k+ context, the lead's next Bash call that is not git or read-only (`lib/read-only-command.mjs`) is denied once with "delegate to runner/implementer (C: cost = calls × context)" (`adviceOnce`: the identical retry runs; the ignored count starts over, so never a loop; subagents never; unknown context never); a subagent whose final report is over a cap its spawn prompt states is sent back once (no stated cap, no check). Fails open.
- `final-reply-cap.mjs` - Stop: blocks once when the final reply is over the line or word cap named in the owner's last prompt ("final reply max 25 lines"). Never blocks twice (`stop_hook_active`); any error exits 0.
- `ui-proof-gate.mjs` - PostToolUse(Bash|PowerShell), Stop, SubagentStop: after every `ui-check run` writes a UI proof record; blocks a Stop (lead) or SubagentStop (ui-implementer, visual-qa) once per state when UI files changed against the merge base and no matching `visual-qa` PASS exists. Always on for UI changes; outside a git work tree the stop passes. The hard bar is `ui-proof check` at landing.
- `git-tidy-gate.mjs` - Stop, SubagentStop, PreCompact: keeps git on one line (C37). A lead's Stop is blocked once per repository state (a hash of all refs and the worktree list; the `git-tidy check --json` verdict is cached per session in `~/.claude/state/git-tidy-gate/<session>.json`, so a repo unchanged for under 10 minutes runs no child) while the check finds an unpublished merge commit, or a `superseded-copy`, `agent-leftover`, merged branch or worktree that a dry run of the advised `git-tidy prune --include-recent` would remove (the reason carries that line, names and paths single-quoted, commit subjects quoted and cut at 200 characters; a fresh worktree at the base, which prune keeps, never blocks); or while an `unlanded-lane?` is named by no open row of the session's STATUS.md (same lookup as `status-deliver.mjs`; none linked: not judged). SubagentStop blocks once when the agent left its own empty `worktree-agent-<id>` branch (`git branch -d`); agents that cannot write files pass. PreCompact prints `open lane <branch>: ...` lines (not for older copies or agent branches). A lead's Stop and PreCompact also gate the worktrees of files the session itself edited with Edit, Write, MultiEdit or NotebookEdit (the `commit-gate` records of `lib/own-edits.mjs`, up to 5 repos, newest first), so a session started in a folder that is no repo (`~`) is checked too: each repo gets the same filter precheck, cache and bound, is blocked once per its own state, and a later repo is skipped once the first ones spent the 4 s; git never runs in a repo of no recorded edit, and a subagent still gates its start folder only. The check child has a 4 s bound (`GIT_TIDY_GATE_CHECK_TIMEOUT_MS` changes it) with core.fsmonitor, log.showSignature and bare repositories off; it is never run when the config view of any worktree of the repo defines a filter; on a timeout the stop passes and a detached refresh fills the cache. Continued stops get at most 2 blocks in a row. Any error: one stderr line, exit 0.
- `status-deliver.mjs` - Stop: runs `tools/status/status.mjs deliver --auto` on the STATUS.md the session last edited with `status.mjs` (its link: `~/.claude/state/estimate/session/<session>.json`), so a turn that ends with no open row and a row done since the last hand-over gets its `deliver:N` row. No link: silent. A linked STATUS.md outside the Stop input's `cwd` and `CLAUDE_PROJECT_DIR` (both resolved with the native realpath, so a cwd typed in another case on macOS or Windows still matches) is left alone, silently; so is one above the cwd: a Stop whose cwd is a subfolder of the project (such as `src/`) and no `CLAUDE_PROJECT_DIR` writes no hand-over. This narrows a wrong target, it does not rule one out: a subagent's `status.mjs` edit moves the shared session's link, and a cwd such as `~` holds every project below it. A linked path that is not a plain `STATUS.md` reached without links, or is over 4 MiB, is refused with one stderr line. Never blocks; any error exits 0.
- `resume-notice.mjs` - SessionStart(startup|resume|compact): tells the lead what work was left open, with no workflow journal: plain writer agents launched with no recorded finish (type, description, agent id, STATUS row, the folder's dirty-file count; SendMessage before a fresh agent), the open questions of recent ask queues with the re-arm line, the "Don't redo" list of the HANDOFF.md beside the STATUS.md (all from `lib/unfinished-work.mjs`), and the Stop-gate records the last notice did not show. Bounded; texts are data without control characters or angle brackets; nothing for a subagent, another source or a bad session id; never fails a session start. Wired in `settings/base.json`, where the retired workflow resume hook stood.
- `disk-clean-start.mjs` - SessionStart(startup): starts `tools/disk-free/disk-clean.mjs --apply` detached in the background at most once every 24 h (stamp `~/.claude/state/disk-clean.stamp`; the last run's output is in `~/.claude/logs/disk-clean.log`). It never waits for the clean-up and never fails the session start; subagents and other sources start nothing.
- `checkpoint.mjs` - PostToolUse, PreCompact: when a main session's transcript grew by about 40k tokens (bytes / 3.5) since the last checkpoint, and on every compaction, starts a detached job (`tools/recall/checkpoint-job.mjs`) that has Haiku write structured notes of the new tail into the recall DB. Returns at once; one job per session (lock file); subagents (`agent_id`) are skipped; never blocks or prints.
- `recall-digest.mjs` - SessionStart(compact): prints this session's checkpoint notes (owner instructions, open items, decisions, key numbers, files; newest first, at most 6000 chars) and the `recall "<query>" --session current` pointer; waits briefly for a running checkpoint. Separate from `session-notes.mjs` so that output keeps its own cap.
- `token-audit.mjs` - manual CLI (not a hook event): prints the approximate recurring token cost of the visible config.

Limits: the guard is a tripwire against mistakes and careless commands, not a sandbox. A command built to hide from it (look-alike characters, exotic shell features, values computed at run time) can still pass or only ask; the permission mode and the dialogs are the boundary.

## lib/

Helpers: `diagnostics.mjs` (a failed format run to `file:line RULE-ID message`) serves `post-edit.mjs`; `edit-log.mjs` (the per-user hook temp root) serves `agent-budget.mjs` and `writer-agents.mjs`; `read-only-command.mjs` (is a Bash command git or reading only) serves `agent-budget.mjs`; `own-edits.mjs` (the files a session or agent changed) serves `commit-gate.mjs`; `writer-agents.mjs` (which agent types write files) serves `agent-model-guard.mjs`, `agent-budget.mjs` and `commit-gate.mjs`; `brief-fields.mjs` (the `worktree:` field of a writer brief, read without lookups) serves `writer-agents.mjs`; `ui-brief-gate.mjs` (the UI brief gate: a `MATRIX:` line or one bounce) serves `agent-model-guard.mjs`; `agent-launches.mjs` (the session's launch record and the agent cap) serves `agent-model-guard.mjs` and `agent-budget.mjs`. `copy-branch-brief.mjs` (a brief that copies an existing branch) serves `agent-model-guard.mjs`. Pure helpers for `pre-bash-guard.mjs`, no I/O:

- `reply-cap.mjs` - parses a reply-size cap from a prompt and measures a reply (used by `agent-budget.mjs` and `final-reply-cap.mjs`).
- `shell-words.mjs` - command text to segments of unquoted words (`tokenize`, regex based) and `lex` (the same shape from `shell-lexer.mjs`, the raw-text backstop); `shell-lexer.mjs` - character-level lexer (quotes, comments, arithmetic, heredocs, `$(...)` in double quotes); `shell-hazards.mjs` - rules for commands that hide what runs (stdin shells, variable command words, `env -S`, `su -c`); `braces.mjs` - brace expansion for rm paths; `raw-risk.mjs` - the fail-to-ask rule: a hidden-execution construct (`$(`, backtick, `<<`, `<(`, eval, trap, case, CR, pipe into a shell, git config read from a file: `GIT_CONFIG_GLOBAL|SYSTEM=`, `include.path`, a value git runs set in a way the guard cannot read) plus a dangerous word anywhere in the raw text asks ("risky word inside shell expansion"), independent of both parsers (the single-quoted argument of echo, printf, grep, rg, jq, sed or `git log` is data, `inert-arguments.mjs`, only in shapes it can prove harmless); a command over 32 KB (`MAX_COMMAND_CHARS` in `verdict.mjs`) is not parsed and asks "command too long to check".
- `ansi-c.mjs` - decoder for `$'...'` quoting (`\xNN`, octal, `\uNNNN`).
- `command-of.mjs` - segment to the real command (and its word index), looking through keywords, `VAR=x` and wrappers.
- `command-checks.mjs` - git, disk-wipe, lockfile, hidden-`rm`, xargs/parallel `rm -r` (also inside a `sh -c` script), keychain and `gh auth token` print, and `gh ssh-key add` (not `*.pub`) rules for one command; `verdict.mjs` - the `DESTRUCTIVE:` prefix.
- `captured-read.mjs` - drops the keychain / `gh auth token` print ask when each read only fills a variable (`export T=$(gh auth token)`).
- `credential-send.mjs` - a private credential file (ssh key or any non-public file under `.ssh`, `.aws/credentials`, `.netrc`, gh `hosts.yml`, kube/npm/docker/pypi configs) and a network sender or cloud upload in one command line, a whole `.ssh`/`.aws`/`.gnupg` folder given to a sender or archived before one, or a credential fed to ssh's stdin; identity-flag values do not count.
- `dangerous-scan.mjs` - finds a dangerous command behind an unknown wrapper; `eval-check.mjs` - `eval` of a variable or substitution.
- `rm-paths.mjs` - `rm -r` target rules (outside the project, or a whole folder: the working directory or a bare glob of it, the project root, home or `/`) and the ordered variable tracking; a variable assigned from a backtick is unknown, as after `$(...)` (both parsers lose a backtick's output).
- `bare-glob.mjs` - which folder the trailing bare globs of an `rm -r` target list (`*`, `./**/*`): one pass from the end of the target, no pattern per path part; `rm-paths.mjs` leaves a target over `MAX_TARGET_CHARS` (4096) unread and asks.
- `cd-folder.mjs` - the folders the guard follows a line through after `cd`, `pushd` or `popd` (the rules are in the module's header).
- `scratch-area.mjs` - the scratch areas where an `rm -r` outside the project runs unasked (owner FR6): below this session's own temp folder or in a `cs-test-*` folder, judged by the real path the rm deletes; no exemption on a line holding a command that may make links.
- `find-delete.mjs` - `find ... -exec rm -r` / `-delete`: the start folders are judged like `rm -r` targets; `-L`/`-follow` always asks.
- `git-runs.mjs` - the commands git itself runs, each checked like a `bash -c` body: a subcommand option's value (`rebase -x`, `filter-branch --*-filter`, `clone --upload-pack`, `grep -O`), `bisect run`, `submodule foreach`, `for-each-repo`, config set for the call whose value runs (`-c core.pager=`, `alias.*`, `credential.helper`, `--config-env`, `GIT_CONFIG_KEY_<n>`, `GIT_CONFIG_PARAMETERS`, clone's own `-c|--config`), what `git config` writes to such a key (a `core.hooksPath` write asks like `-c`), `GIT_SSH_COMMAND`, `GIT_PAGER`, `EDITOR` and the other variables git runs, `ext::` URLs and `git remote-ext <remote> <command>`. A `--config-env` variable the line does not set, or `ext::` switched on, asks "git runs a command this guard cannot read"; `raw-risk.mjs` asks the same next to a dangerous word when such a value is set in a way the guard cannot read (`printf -v`, `read`, `"$A$B"`).
- `git-run-values.mjs` - the value of each variable git runs (`GIT_EDITOR`, `GIT_PAGER`, `GIT_SSH_COMMAND`, `EDITOR` ...) wherever a command line assigns it (in front of a command, `export`, `declare -x`, a plain statement, `${NAME:=value}`), checked as a command; a value it cannot read (`$(...)`, a backtick, another variable) asks, except one reference to a variable the line does not write (`"$EDITOR"`). `judgeOnce` checks each distinct text git or such a value runs once per line, so repeats cost nothing.
- `inert-arguments.mjs` - empties the single-quoted arguments of programs that never run them (echo, printf, grep, rg, jq, sed without `e`/`w`/`-i`, `git log` without `--output`) for `raw-risk.mjs`; any shape where the quoted text could still run or be read differently from the shell leaves the text unchanged.
- `git-advice.mjs` - the three git advices in one call (merge commit, branch move, copy of a lane branch); the copy-branch advice asks git (hardened, one 2 s budget per command line) and any error gives no advice.
- `message-text.mjs` - blanks the quoted message of `git commit` / `gh pr|issue create|edit|comment` so `raw-risk.mjs` reads it as data.
- `secrets.mjs` - literal secret detection (returns a kind, never the value) and `maskSecrets`; a TypeScript type (`cookie: string`) and a boolean or 1-2 digit flag (`passwordReset=1`) are not secrets.
- `data-text.mjs` - the data text that `secrets.mjs` reads only for known token shapes, named secret variables and env-file assignment lines (`API_TOKEN=x`): a quoted-delimiter heredoc body stored by a bare `cat` or `tee` while every other statement is a quiet command (cd, mkdir, chmod, ls, echo ...) with no substitution and nothing sets `PATH=` or another variable that changes what runs, else the single-quoted arguments of `inert-arguments.mjs`; a body a later statement runs or reads (`bash x.sh`, `xargs curl < f`, `source f`), inside `{ }`, a loop or an `if`, or next to `exec`/`coproc` is scanned whole.
- `outward.mjs` - push, gh release, gh pr merge and publish asks.
- `timed-ask.mjs` - the timed native dialog (osascript / PowerShell popup / zenity with `--no-markup`; `timed-ask-async.mjs` runs it as a closable child for the question popups), 2 min by default (`CLAUDE_ASK_TIMEOUT_S`; a caller may pass its own `timeoutS`, as `permission-timed-allow.mjs` does with `CLAUDE_PERMISSION_TIMEOUT_S`), fallback to the native ask. Shown values are masked first (with their real line breaks, before anything is flattened or cut), then put on one line (line breaks become a visible mark; control, format, bidi, zero-width and other default-ignorable characters are dropped) and cut to head + tail + length (a detail line may keep its start instead; its label is masked and cut too). On macOS the decline button is the cancel button, so Esc declines and never takes the default.
- `answered-commands.mjs` - hands a guard dialog's allow to `permission-timed-allow.mjs` (`~/.claude/state/guard-answered/<session>.json`, a 0700 per-user folder and 0600 file, links refused; sha256 of agent, directory and exact command; used once; window 10 s after the guard's answer), so one command never gets two dialogs. Any process of the same user can still write a record inside that window and skip one dialog for that exact command, except a command the guard classes as DESTRUCTIVE, which never uses the hand-over.
- `allowed-literals.mjs` - per-session sha256 memory of literal secrets the owner allowed (`~/.claude/state/guard-allowed/<session>.json`, file 0600, directory 0700; never a raw value).
- `bounce-once.mjs` - the one-time bounce of a command the agent can rewrite, with its deny text (`~/.claude/state/guard-bounced/<session>.json`, hashes only); its `adviceOnce` also serves `agent-model-guard.mjs`; `reason-classes.mjs` - a fixed class name for every guard reason, so the bounce knows what it may bounce and names the rest without command text.
- `session-store.mjs` - the per-session store files of `allowed-literals.mjs` and `bounce-once.mjs`: lstat-checked, never through a link, never waiting on a FIFO, cleanup of its own old files only.
- `session-lock.mjs` - `withSessionLock`, built on `session-store.mjs`: a lock file (`<pid> <token>`, removed only by its holder, taken over only from a gone pid after 0.5 s or from anyone after 5 s, one waiter at a time, behind a `<lock>.break` file that others treat as a busy lock; it is read again under that file and renamed aside only while it is still the stale one, else linked back; in a rare double release-and-take the moved lock can still be lost) lets hooks recording at the same moment take turns. A caller waits up to 1 s; one that must not wait (the status line's limit sample) passes `waitMs: 0` and tries once.
- `guard-log.mjs` - masked JSON-line decision log (`~/.claude/logs/guard.jsonl`, `CLAUDE_GUARD_LOG`; at 5 MB it moves to `guard.1.jsonl` under a lock and an empty log replaces it in one rename; file 0600, directory 0700; a link, FIFO or device at the log path is never followed, written or waited on).
- `plain-file.mjs` - the one safe open (no waiting, no link followed, regular files only, no append to a hard-linked file, a size cap) for the host list, the decision log and the edit log.
- `remote.mjs` - production-host list (a list file that is not a plain file makes every host ask) and the ssh/scp/rsync/psql/mysql write classifier; `sql.mjs` - statement-level read-only SQL check and host detection.
