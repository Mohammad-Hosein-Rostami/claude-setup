# home/hooks

Claude Code hooks installed to `~/.claude/hooks` (a symlink to this folder). All are Node 22 scripts with no dependencies.

- `project-merge.mjs` - SessionStart (startup, resume, clear, compact, fork; the main session only): says what the project's own AI setup brings beside ours (CLAUDE.md, AGENTS.md and whether it loads, `.claude/rules`, skills with the ones ours hide by name and their paths, agents with `maxTurns`, hooks, settings that change ours, MCP servers), warns when the project turns all hooks off (`disableAllHooks`) or may hide our CLAUDE.md (`claudeMdExcludes`), and adds the project's note found by its repo key (`home/project-notes/<key>.md`, then `~/.claude/project-notes/<key>.md`; a note `CLAUDE.local.md` imports by that very file is named, not repeated). Agents get nothing from it. Its own hook string (JSON `additionalContext`), at most 6,000 characters; repository names and values are labelled as data and quoted; read-only, no state; one 4 s deadline below the 5 s timeout. Prints nothing for a project with no AI files and no note, in HOME, or for a SessionStart inside a subagent.
- `notify.mjs` - Notification(permission_prompt, elicitation_*, quota_auto_resume_stale|disabled), StopFailure(rate_limit): the desktop notes of display design 7.10 (needs you, with the question's short header, limit stopped work) as `terminalSequence`, on the owner's `preferredNotifChannel`.
- `question-answered.mjs` - PostToolUse and PostToolUseFailure(AskUserQuestion): writes the mark (`~/.claude/state/question-answered/<session>.json`, sha256 of agent and question texts, 0700 folder and 0600 file, links refused, dropped after 15 min) that tells `question-popup.mjs` the owner answered in the terminal, so its popup closes, and clears the asking marker. A mark older than the popup never closes it. Prints nothing, always exits 0.
- `question-popup.mjs` - PermissionRequest(AskUserQuestion): one dialog per question, one after the other (`lib/question-reply.mjs`; "Use recommended" is the default (Enter) button of question 1 only; questions 2..N default to "Answer in terminal" so an Enter typed in the terminal question cannot answer, and "Use recommended" stays clickable; title "question 2 of 3"), each with its own 2 min wait, showing that question (its header inside the masked, cut value) and on its own `Answer:` line the start of the option to be taken; no answer in that question's 2 min or "Use recommended" takes its "(Recommended)" option, else its first (multiSelect gets that one option), and after the last question the hook allows with `updatedInput` = the input plus `answers`; on a timeout only, `annotations` adds to that question's answer the note "No answer in 2 min: this option was taken by default, not chosen by the owner (UNCONFIRMED)", which Claude Code shows Claude in the tool result; "Answer in terminal" (Esc on macOS), no GUI or a failed dialog on any question print nothing (Claude Code's own question UI, which shows every question; never an invented answer). When the owner answers in the terminal the open popup closes within 0.25 s and no later one opens: Claude Code runs this hook beside its own question and tells it nothing, so `question-answered.mjs` (PostToolUse(AskUserQuestion)) leaves a mark that the popup loop polls; a turn-down in the terminal ("Chat about this", Esc) runs no tool, so the session transcript is watched for it too (`lib/question-rejected.mjs`). Claude Code stopping the hook (SIGTERM, SIGINT, SIGHUP) also closes the open popup. The hook timeout in `settings/base.json` is 800 s: 4 questions at most 190 s each.
- `post-edit.mjs` - PostToolUse(Edit|Write|MultiEdit): runs the project's own `format` script on the edited file (`CLAUDE_POST_EDIT_SKIP=all|format` skips it, but not when only the project's committed `.claude/settings.json` sets it: then it runs and warns once per session, `lib/team-switch.mjs`). Any other script runs through the package manager only in a project you trust with `CLAUDE_POST_EDIT_TRUST_FORMAT=1` (shell or untracked `.claude/settings.local.json`); elsewhere only one plain call of a known formatter runs, as the tool's binary, and anything else is not run, with one warning per session (`lib/format-trust.mjs`). It runs no lint and no typecheck. By design:
  - Not closed without trust: a known formatter still reads the repo's own config (`prettier.config.js`, `eslint.config.js` and plugins named there run code) and may be the repo's own `node_modules/.bin` binary. Only trust settles that, so open a repo you do not know with care.
  - A script that is more than one plain call (`prettier --write "src/**/*.ts"` with its quotes, `a && b`) runs only with trust; the warning says how to set it.
  - Trust covers every `package.json` inside the trusted project folder, a nested or vendored package included.
- `git-tidy-gate.mjs` - SessionStart(startup, resume): names the lanes of the session's repository that are not landed yet (`unlanded-lane?` of `git-tidy check --json`, each subject once; `lib/tidy-gate-notes.mjs`), so a new or resumed session sees leftover work at once. It never blocks. The verdict is cached per session in `~/.claude/state/git-tidy-gate/<session>.json` (a hash of all refs and the worktree list), so a repo unchanged for under 10 minutes runs no child. The check child has a 4 s bound (`GIT_TIDY_GATE_CHECK_TIMEOUT_MS` changes it) with core.fsmonitor, log.showSignature and bare repositories off; it is never run when the config view of any worktree of the repo defines a filter; on a timeout nothing is said and a detached refresh fills the cache. Input that is not JSON: silent, exit 0; any other error: one stderr line, exit 0. `tools/land` lands a lane.
- `disk-clean-start.mjs` - SessionStart(startup): starts `tools/disk-free/disk-clean.mjs --apply` detached in the background at most once every 24 h (stamp `~/.claude/state/disk-clean.stamp`; the last run's output is in `~/.claude/logs/disk-clean.log`). It never waits for the clean-up and never fails the session start; subagents, other sources and input that is not JSON start nothing.

## lib/

Helpers: `diagnostics.mjs` (a failed format run to `file:line RULE-ID message`) serves `post-edit.mjs`; `edit-log.mjs` (the per-user hook temp root) serves `team-switch.mjs`; `writer-agents.mjs` (which agent types write files) serves the board (`tools/board/lib/agents.mjs`) and `gated-folder.mjs`. Shared by the question popup and the stores:

- `secrets.mjs` - `maskSecrets`: every literal secret in a dialog text becomes `[masked]`; a TypeScript type (`cookie: string`) and a boolean or 1-2 digit flag (`passwordReset=1`) are not secrets.
- `timed-ask.mjs` - the timed native dialog of the question popups (osascript / PowerShell popup / zenity with `--no-markup`; `timed-ask-async.mjs` runs it as a closable child), 2 min by default (`CLAUDE_ASK_TIMEOUT_S`; a caller may pass its own `timeoutS`, as `question-reply.mjs` does with `CLAUDE_QUESTION_TIMEOUT_S`), fallback to Claude Code's own question UI. Shown values are masked first (with their real line breaks, before anything is flattened or cut), then put on one line (line breaks become a visible mark; control, format, bidi, zero-width and other default-ignorable characters are dropped) and cut to head + tail + length (a detail line may keep its start instead; its label is masked and cut too). On macOS the decline button is the cancel button, so Esc declines and never takes the default.
- `session-store.mjs` - small per-session store files (`asking-marker.mjs`, `question-answered.mjs` and others): lstat-checked, never through a link, never waiting on a FIFO, cleanup of its own old files only.
- `session-lock.mjs` - `withSessionLock`, built on `session-store.mjs`: a lock file (`<pid> <token>`, removed only by its holder, taken over only from a gone pid after 0.5 s or from anyone after 5 s, one waiter at a time, behind a `<lock>.break` file that others treat as a busy lock; it is read again under that file and renamed aside only while it is still the stale one, else linked back; in a rare double release-and-take the moved lock can still be lost) lets hooks recording at the same moment take turns. A caller waits up to 1 s; one that must not wait (the status line's limit sample) passes `waitMs: 0` and tries once.
- `plain-file.mjs` - the one safe open (no waiting, no link followed, regular files only, no append to a hard-linked file, a size cap) for the files the hooks and tools read or append.
