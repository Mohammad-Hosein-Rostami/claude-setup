# home/hooks

Claude Code hooks installed to `~/.claude/hooks` (a symlink to this folder). All are Node 22 scripts with no dependencies.

- `project-merge.mjs` - SessionStart (startup, resume, clear, compact, fork; the main session only): says what the project's own AI setup brings beside ours (CLAUDE.md, AGENTS.md and whether it loads, `.claude/rules`, skills with the ones ours hide by name and their paths, agents with `maxTurns`, hooks, settings that change ours, MCP servers), warns when the project turns all hooks off (`disableAllHooks`) or may hide our CLAUDE.md (`claudeMdExcludes`), and adds the project's note found by its repo key (`home/project-notes/<key>.md`, then `~/.claude/project-notes/<key>.md`; a note `CLAUDE.local.md` imports by that very file is named, not repeated). Agents get nothing from it. Its own hook string (JSON `additionalContext`), at most 6,000 characters; repository names and values are labelled as data and quoted; read-only, no state; one 4 s deadline below the 5 s timeout. Prints nothing for a project with no AI files and no note, in HOME, or for a SessionStart inside a subagent.
- `pre-bash-guard.mjs` - PreToolUse(Bash, and PowerShell calls too, which its shell rules read only as plain words): never blocks for good. Since the 2026-11-24 audit (H1) these ask as well: a variable inside the command word (`git$IFS'push'`) and `$IFS` anywhere outside single quotes, an interpreter fed its code by a pipe, a file or text the shell fills in (`base64 -d | python3`, `python3 <<< "$(x)"`), interpreter code that builds the command it runs from pieces and PowerShell `-EncodedCommand` (`lib/inline-code.mjs`), the merge and release verbs and `api` writes of glab, hub and tea, a git subcommand holding an unset variable (`git ${x}push`), and every `git update-ref` (an ask each time, the branch-move advice beside it). A plain foreground test or build runner call it lets run is rewritten to print the log path, then only its last 150 lines (`lib/output-trim.mjs`; opt-in: `CLAUDE_GUARD_TRIM=1` in the env of your settings/local.json turns it on, since a project allow rule such as `Bash(pnpm test:*)` does not match the rewritten command). A command with a hit that a rewrite fixes (a variable command word, a risky word inside shell expansion, a word or arithmetic known only at run time such as `read X; git $X` or `$(( $(cat n) + 1 ))`) is first bounced back once with the fix (`lib/bounce-once.mjs`), and the bounce names every other reason that will still ask after the rewrite; the identical command sent again gets the dialog (without a GUI, the CLI's ask). A plain `for` list (`for d in a b; do rm -rf "$d"; done`) is judged once per value (`lib/loop-values.mjs`). A literal secret (a test password, a token) asks nothing and is never bounced (owner decision R22-G1): the log gets one line with outcome `secret` that names its kind, never the value or the command; gitleaks still checks commits. Quality rules (a hand-edited lockfile, `docker rm` without `-v`, which leaves anonymous volumes on disk: `lib/docker-advice.mjs`, a `git merge` or `git pull` that can make a merge commit, a branch moved by `update-ref` (a literal branch or HEAD, a ref in a variable, `--stdin` text setting anything but a literal ref outside refs/heads/), `branch -f`, `push|fetch .` or `fetch -u <repo>` instead of `merge --ff-only`: `lib/branch-move.mjs`; git itself refuses `branch -f` and a plain `fetch|push .` onto a branch checked out in any worktree, the advice stays for the rest; a copy of an existing lane branch (`checkout -b x-2` while `x` exists): `lib/git-advice.mjs`, which asks git under one 2 s budget; a wait by sleeping, a `for|while|until` loop that sleeps 5 s or more or one `sleep` of 30 s or more, unless the call is sent with `run_in_background: true`: `lib/wait-advice.mjs`) are advice, never a dialog: the first send comes back with the fix and the identical command sent again runs. Rules (--no-verify, force push, rm -r outside the project, rm -r of a whole folder inside it (the working directory itself, or a bare glob such as `*`, `./*`, `.*`, `./**/*` of the working directory, the project root, home, a temp root or `/`: `rm -rf *` asks, `rm -rf src/*` and `rm -rf *.log` do not) or run by xargs/parallel (also in their `sh -c` script), disk wipes, printing a keychain secret or `gh auth token`, `gh ssh-key add` of a non-`.pub` file, a credential file or folder next to a network sender, cloud upload or ssh stdin, push, gh release/pr merge, publish, prod-host writes) open a timed dialog: Allow by default, no answer in 2 min (max 190) goes ahead, Deny on click, native ask when there is no GUI or the dialog failed. Allow and timeout print no decision, so the normal permission flow and deny rules still apply. Commands inside a command get the same rules, their reasons joined to the outer command's (deeper than 24 levels asks): `bash -c`, `eval` and `$(...)` bodies, and every command git itself runs (`lib/git-runs.mjs`). Git's own programs (`git-push`, `<exec path>/git-rebase`) count as `git <sub>`, a `git config` value is read also when it is dashed or follows `--`, and the value of a variable git runs (`GIT_EDITOR`, `GIT_PAGER`, `GIT_SSH_COMMAND` ...) is checked wherever the line assigns it, with git after it or not (`lib/git-run-values.mjs`; a value it cannot read asks "git runs a command this guard cannot read" unless it is one reference such as `"$EDITOR"`). Command words are folded the way macOS and Windows match names (`GIT push`, `/BIN/RM`, `ſh` is sh); a command word still outside ASCII after that asks next to a dangerous word. Git-run variable names ignore case on Windows (`git_editor`), and are exact elsewhere. `NAME+=x` and `NAME[i]=x` in front of a command are assignments; unquoted brace words are expanded as bash does (`rm {-rf,x}`), and one the guard cannot list asks in a command it checks; an unquoted variable whose value has blanks is judged as each word bash splits it into. Logs decisions and `sed -i`/heredoc code writes (for the typecheck gate). It never fails open on its own errors: a failure in its code after the rules asks ("guard error: <error class>", logged as `guard-error`), and `"onFailure": "block"` on its entry in `settings/base.json` blocks the call when the hook dies or times out.
- `notify.mjs` - Notification(permission_prompt, elicitation_*, quota_auto_resume_stale|disabled), StopFailure(rate_limit): the desktop notes of display design 7.10 (needs you, with the question's short header, limit stopped work) as `terminalSequence`, on the owner's `preferredNotifChannel`.
- `artifact-ask.mjs` - PreToolUse(Artifact): the same timed dialog before an Artifact publish or delete.
- `question-answered.mjs` - PostToolUse and PostToolUseFailure(AskUserQuestion): writes the mark (`~/.claude/state/question-answered/<session>.json`, sha256 of agent and question texts, 0700 folder and 0600 file, links refused, dropped after 15 min) that tells `permission-timed-allow.mjs` the owner answered in the terminal, so its popup closes, and clears the asking marker. A mark older than the popup never closes it. Prints nothing, always exits 0.
- `permission-timed-allow.mjs` - PermissionRequest(`*`): every Claude Code permission prompt (any tool incl. MCP tools, Agent and ExitPlanMode plan approval (its allow echoes `updatedInput`), protected-file writes, ask rules; any permission mode; interactive, background agents and `claude -p`, where Claude Code runs this hook too) gets the timed dialog with a 2 min wait (`CLAUDE_PERMISSION_TIMEOUT_S`, max 190): no answer or Allow allows, Deny (Esc on macOS) denies; no GUI prints nothing (the normal prompt, or Claude Code's deny where nobody can be asked). AskUserQuestion gets one dialog per question, one after the other (`lib/question-reply.mjs`; "Use recommended" is the default (Enter) button of question 1 only; questions 2..N default to "Answer in terminal" so an Enter typed in the terminal question cannot answer, and "Use recommended" stays clickable; title "question 2 of 3"), each with its own 2 min wait, showing that question (its header inside the masked, cut value) and on its own `Answer:` line the start of the option to be taken; no answer in that question's 2 min or "Use recommended" takes its "(Recommended)" option, else its first (multiSelect gets that one option), and after the last question the hook allows with `updatedInput` = the input plus `answers`; on a timeout only, `annotations` adds to that question's answer the note "No answer in 2 min: this option was taken by default, not chosen by the owner (UNCONFIRMED)", which Claude Code shows Claude in the tool result; "Answer in terminal" (Esc on macOS), no GUI or a failed dialog on any question print nothing (Claude Code's own question UI, which shows every question; never an invented answer). When the owner answers in the terminal the open popup closes within 0.25 s and no later one opens: Claude Code runs this hook beside its own question and tells it nothing, so `question-answered.mjs` (PostToolUse(AskUserQuestion)) leaves a mark that the popup loop polls; a turn-down in the terminal ("Chat about this", Esc) runs no tool, so the session transcript is watched for it too (`lib/question-rejected.mjs`). Claude Code stopping the hook (SIGTERM, SIGINT, SIGHUP) also closes the open popup. The hook timeout in `settings/base.json` is 800 s: 4 questions at most 190 s each. The dialog labels the target (`Command:`, `File:`, `Path:`, `URL:`, `Query:`, `Plan:`, `Input:`) and says what the tool asks to do in which mode; for Bash it runs the guard's rules and for Artifact the Artifact hook's, and shows that hook's own reason (e.g. the guard's DESTRUCTIVE reason, or Artifact publish / delete) when they ask. An `Input:` (MCP and other JSON input) has every secret-named field (`password`, `apiKey`, `X-Api-Key`, `Authorization`, at any depth) masked in the dialog and the log. A Bash command the guard's dialog allowed moments before is allowed with no second dialog (`lib/answered-commands.mjs`), unless the guard classes it as DESTRUCTIVE: that one always gets the dialog.
- `agent-model-guard.mjs` - PreToolUse(Agent|Task) and PreToolUse(SendMessage), an entry that loads `lib/agent-model-gates.mjs` inside a try (a lib that fails to load, or a crash, denies the call): sets `model: sonnet` on a general-purpose / Explore / built-in call that has none (general-purpose pins no model, so it would get `CLAUDE_CODE_SUBAGENT_MODEL`, or the lead model when that is unset; Explore and Plan say `model: inherit`, which skips that variable, so they would run on the lead model); Plan gets `opus` (built-in types match in any case, so `explore` and `plan` too). Forks are untouched; an agent file's `model` and `effort` are a floor: a lower per-call value is left out (`lib/agent-pins.mjs`). Gates, in order, the first deny wins: (R) the main-agent route (`lib/agent-route.mjs` `mainRouteReason`): the main session starts only lex, dev and tess (and Claude Code's claude-code-guide and statusline-setup), any other type is denied every time with the route to take, and a subagent starting lex, dev or tess is denied every time (it asks the boss with a `needs:` line); (0) no Fable for an agent, denied every time and fail closed (`fableReason`, reasons in `lib/fable-model-reasons.mjs`): a Fable or `inherit` model in the call, or an alias Claude Code resolves only at run time (`best` may be Fable; `default`, `opusplan`); with none, an agent file pinning Fable, such an alias, `inherit` or nothing (with no, a Fable or an alias `CLAUDE_CODE_SUBAGENT_MODEL`); with `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` on (Claude Code then ignores the call's model and the pin), a `CLAUDE_CODE_SUBAGENT_MODEL` that is unset, `inherit`, Fable or such an alias, a pin that cannot be read or is not certain, or a type with no agent file it reads (a plugin agent, a fork, an unknown type: it runs only with a non-Fable `model`); bad stdin and a crash deny the call; (1) copy-branch brief (`lib/copy-branch-brief.mjs`): a writer brief that creates a copy of an existing branch (`<lane>-2`, `-fix`, `-v2`, `-redo`) or says "new branch off <existing>" is sent back once with the same-branch steps (read up to 32 KB, in linear time: the hook has a 5 s timeout); (2) UI brief (`lib/ui-brief-gate.mjs`): a `dev-pixel` or `pixel-qa` call whose prompt has no line `MATRIX: <path>` naming a coverage matrix (or `MATRIX: none: <reason>`) is denied once with the `ui-coverage init` advice; (3) main-agent cap (`agent-budget.mjs` `claimMainSlot`): at most 3 lex, 3 dev and 3 tess started by the main session run at once, denied every time while full or when the record cannot be read; helpers started by another agent are never routed or capped; (4) writer isolation (`lib/writer-agents.mjs`, `lib/agent-launches.mjs`): a writer (dev, dev-ui, dev-pixel, dev-debug, tess-write, or an agent file that writes) launched while another writer of the session runs needs `isolation: "worktree"` or a `worktree: <abs path>` brief line naming a free linked worktree, else it is denied once with that advice. A deny-once gate lets the identical call through when it is sent again (`adviceOnce`). On SendMessage only the resume cap runs (`agent-budget.mjs` `resumeCapReason`): a message that would resume a stopped lex, dev or tess while 3 of its type run is denied every time.
- `post-edit.mjs` - PostToolUse(Edit|Write|MultiEdit): runs the project's own `format` script on the edited file (`CLAUDE_POST_EDIT_SKIP=all|format` skips it, but not when only the project's committed `.claude/settings.json` sets it: then it runs and warns once per session, `lib/team-switch.mjs`). Any other script runs through the package manager only in a project you trust with `CLAUDE_POST_EDIT_TRUST_FORMAT=1` (shell or untracked `.claude/settings.local.json`); elsewhere only one plain call of a known formatter runs, as the tool's binary, and anything else is not run, with one warning per session (`lib/format-trust.mjs`). Even then the formatter reads the repo's own config (`prettier.config.js`, `eslint.config.js` can run code), so trust only repos you know. It runs no lint and no typecheck.
- `agent-budget.mjs` - PostToolUse (all tools, async), SubagentStart, SubagentStop; called by `agent-model-guard.mjs`: the main-agent route (`lib/agent-route.mjs` `mainRouteReason`: the main session starts only lex, dev and tess; a helper such as `lex-web` or `tess-write` is denied with the name of the agent that starts it) and cap (at most 3 of each main agent type, lex, dev and tess started by the main session, run at once, `MAX_AGENTS_PER_TYPE`; the 4th of a type is denied naming its running ids; claude-code-guide and statusline-setup take no slot; a subagent may not start lex, dev or tess; the helpers it starts are never routed or capped). It records each main launch (`~/.claude/state/main-agents/<session>.json` under the session lock, `lib/main-agents-store.mjs`), matches it on SubagentStart, ends it on SubagentStop (keeping the stopped agent's type, so a SendMessage resume is capped by `resumeCapReason`), frees a full type's slot whose agent the lead's transcript shows ended (`lib/agent-ends.mjs`: an agent that died on an API error gets no SubagentStop), and appends a subagent's tool calls to its call counter (its last sign of work, also read by `lib/agent-launches.mjs`). A launch dated ahead of the clock counts as dated now; an unusable or corrupt record denies (fail closed); its own events fail open. Prints nothing: no call notices, nudges or report caps.
- `git-tidy-gate.mjs` - SessionStart(startup, resume): names the lanes of the session's repository that are not landed yet (`unlanded-lane?` of `git-tidy check --json`, each subject once; `lib/tidy-gate-notes.mjs`), so a new or resumed session sees leftover work at once. It never blocks. The verdict is cached per session in `~/.claude/state/git-tidy-gate/<session>.json` (a hash of all refs and the worktree list), so a repo unchanged for under 10 minutes runs no child. The check child has a 4 s bound (`GIT_TIDY_GATE_CHECK_TIMEOUT_MS` changes it) with core.fsmonitor, log.showSignature and bare repositories off; it is never run when the config view of any worktree of the repo defines a filter; on a timeout nothing is said and a detached refresh fills the cache. Input that is not JSON: silent, exit 0; any other error: one stderr line, exit 0. The pre-bash guard keeps refusing merge commits and `update-ref`; `tools/land` lands a lane.
- `disk-clean-start.mjs` - SessionStart(startup): starts `tools/disk-free/disk-clean.mjs --apply` detached in the background at most once every 24 h (stamp `~/.claude/state/disk-clean.stamp`; the last run's output is in `~/.claude/logs/disk-clean.log`). It never waits for the clean-up and never fails the session start; subagents, other sources and input that is not JSON start nothing.

Per-person switches (the `env` of your own git-ignored `settings/local.json`; teammates who do not set them keep the default):
- `CLAUDE_GUARD_ASK=allow` - no confirm dialog and no wait: every ask of our hooks (the Bash guard, the permission prompts of
  `permission-timed-allow.mjs`) is allowed at once (outcome `switch-allow` in the guard log), read once in `lib/timed-ask.mjs`. Lookup order: the hook's own env;
  when it is unset there, `env.CLAUDE_GUARD_ASK` of `$CLAUDE_CONFIG_DIR/settings.json` (else `~/.claude/settings.json`), read at most once
  per hook run, so a session started before the switch was set obeys it too (a hook inherits only the env claude started with); a
  missing or broken file means off. Outward
  actions still get the dialog (the rule "confirm every outward-facing action"): push, publish, PR merge, release, forge and `gh api`
  writes, prod-host writes, a credential next to a sender, an Artifact publish or delete, any MCP tool; so does a command whose real
  action the guard cannot see (a variable command word, built inline code, stdin into a shell, "command too complex" ...), since it may be
  one of those (`keepsDialog` in `lib/reason-classes.mjs`). Denies and the first-send bounces stay as they are. Any other value: the dialog.
- `CLAUDE_GUARD_TRIM=1` - the guard's output trim of test and build runs (`lib/output-trim.mjs`); off by default because a project allow
  rule such as `Bash(pnpm test:*)` does not match the rewritten command.

Limits: the guard is a tripwire against mistakes and careless commands, not a sandbox. A command built to hide from it (look-alike characters, exotic shell features, values computed at run time) can still pass or only ask; the permission mode and the dialogs are the boundary.

## lib/

Helpers: `diagnostics.mjs` (a failed format run to `file:line RULE-ID message`) serves `post-edit.mjs`; `edit-log.mjs` (the per-user hook temp root) serves `writer-agents.mjs` and `team-switch.mjs`; `writer-agents.mjs` (which agent types write files) serves `agent-model-guard.mjs` and `agent-budget.mjs`; `brief-fields.mjs` (the `worktree:` field of a writer brief, read without lookups) serves `writer-agents.mjs`; `ui-brief-gate.mjs` (the UI brief gate: a `MATRIX:` line or one bounce) serves `agent-model-guard.mjs`; `agent-launches.mjs` (the session's launch record for the writer gate) serves `agent-model-guard.mjs` and `agent-budget.mjs`. `copy-branch-brief.mjs` (a brief that copies an existing branch) serves `agent-model-guard.mjs`. Pure helpers for `pre-bash-guard.mjs`, no I/O:

- `shell-words.mjs` - command text to segments of unquoted words (`tokenize`, regex based) and `lex` (the same shape from `shell-lexer.mjs`, the raw-text backstop); `shell-lexer.mjs` - character-level lexer (quotes, comments, arithmetic, heredocs, `$(...)` in double quotes); `shell-hazards.mjs` - rules for commands that hide what runs (stdin shells, variable command words, `env -S`, `su -c`); `braces.mjs` - brace expansion for rm paths; `raw-risk.mjs` - the fail-to-ask rule: a hidden-execution construct (`$(`, backtick, `<<`, `<(`, eval, trap, case, CR, pipe into a shell, git config read from a file: `GIT_CONFIG_GLOBAL|SYSTEM=`, `include.path`, a value git runs set in a way the guard cannot read) plus a dangerous word anywhere in the raw text asks ("risky word inside shell expansion"), independent of both parsers (the single-quoted argument of echo, printf, grep, rg, jq, sed or `git log` is data, `inert-arguments.mjs`, only in shapes it can prove harmless); a command over 32 KB (`MAX_COMMAND_CHARS` in `verdict.mjs`) is not parsed and asks "command too long to check".
- `ansi-c.mjs` - decoder for `$'...'` quoting (`\xNN`, octal, `\uNNNN`).
- `command-of.mjs` - segment to the real command (and its word index), looking through keywords, `VAR=x` and wrappers.
- `command-checks.mjs` - git (`git update-ref` asks every time; hub gets these git rules too), disk-wipe, lockfile, hidden-`rm`, xargs/parallel `rm -r` (also inside a `sh -c` script), keychain and `gh auth token` print, and `gh ssh-key add` (not `*.pub`) rules for one command; `verdict.mjs` - the `DESTRUCTIVE:` prefix.
- `captured-read.mjs` - drops the keychain / `gh auth token` print ask when each read only fills a variable (`export T=$(gh auth token)`).
- `credential-send.mjs` - a private credential file (ssh key or any non-public file under `.ssh`, `.aws/credentials`, `.netrc`, gh `hosts.yml`, kube/npm/docker/pypi configs) and a network sender or cloud upload in one command line, a whole `.ssh`/`.aws`/`.gnupg` folder given to a sender or archived before one, or a credential fed to ssh's stdin; identity-flag values do not count.
- `dangerous-scan.mjs` - finds a dangerous command behind an unknown wrapper (glab, hub and tea count); `eval-check.mjs` - `eval` of a variable or substitution.
- `rm-paths.mjs` - `rm -r` target rules (outside the project, or a whole folder: the working directory or a bare glob of it, the project root, home or `/`) and the ordered variable tracking; a variable assigned from a backtick is unknown, as after `$(...)` (both parsers lose a backtick's output).
- `bare-glob.mjs` - which folder the trailing bare globs of an `rm -r` target list (`*`, `./**/*`): one pass from the end of the target, no pattern per path part; `rm-paths.mjs` leaves a target over `MAX_TARGET_CHARS` (4096) unread and asks.
- `cd-folder.mjs` - the folders the guard follows a line through after `cd`, `pushd` or `popd` (the rules are in the module's header).
- `scratch-area.mjs` - the scratch areas where an `rm -r` outside the project runs unasked (owner FR6): below this session's own temp folder or in a `cs-test-*` folder, judged by the real path the rm deletes; no exemption on a line holding a command that may make links.
- `find-delete.mjs` - `find ... -exec rm -r` / `-delete`: the start folders are judged like `rm -r` targets; `-L`/`-follow` always asks.
- `git-runs.mjs` - the commands git itself runs, each checked like a `bash -c` body: a subcommand option's value (`rebase -x`, `filter-branch --*-filter`, `clone --upload-pack`, `grep -O`), `bisect run`, `submodule foreach`, `for-each-repo`, config set for the call whose value runs (`-c core.pager=`, `alias.*`, `credential.helper`, `--config-env`, `GIT_CONFIG_KEY_<n>`, `GIT_CONFIG_PARAMETERS`, clone's own `-c|--config`), what `git config` writes to such a key (a `core.hooksPath` write asks like `-c`), `GIT_SSH_COMMAND`, `GIT_PAGER`, `EDITOR` and the other variables git runs, `ext::` URLs and `git remote-ext <remote> <command>`. A `--config-env` variable the line does not set, or `ext::` switched on, asks "git runs a command this guard cannot read"; `raw-risk.mjs` asks the same next to a dangerous word when such a value is set in a way the guard cannot read (`printf -v`, `read`, `"$A$B"`).
- `git-run-values.mjs` - the value of each variable git runs (`GIT_EDITOR`, `GIT_PAGER`, `GIT_SSH_COMMAND`, `EDITOR` ...) wherever a command line assigns it (in front of a command, `export`, `declare -x`, a plain statement, `${NAME:=value}`), checked as a command; a value it cannot read (`$(...)`, a backtick, another variable) asks, except one reference to a variable the line does not write (`"$EDITOR"`). `judgeOnce` checks each distinct text git or such a value runs once per line, so repeats cost nothing.
- `inert-arguments.mjs` - empties the single-quoted arguments of programs that never run them (echo, printf, grep, rg, jq, sed without `e`/`w`/`-i`, `git log` without `--output`) for `raw-risk.mjs`; any shape where the quoted text could still run or be read differently from the shell leaves the text unchanged.
- `git-advice.mjs` - the three git advices in one call (merge commit, branch move, copy of a lane branch); the copy-branch advice asks git (hardened, one 2 s budget per command line) and any error gives no advice.
- `message-text.mjs` - blanks the quoted message of `git commit` / `gh pr|issue create|edit|comment` so `raw-risk.mjs` reads it as data.
- `secrets.mjs` - literal secret detection (returns a kind, never the value) and `maskSecrets`; a TypeScript type (`cookie: string`) and a boolean or 1-2 digit flag (`passwordReset=1`) are not secrets.
- `data-text.mjs` - the data text that `secrets.mjs` reads only for known token shapes, named secret variables and env-file assignment lines (`API_TOKEN=x`): a quoted-delimiter heredoc body stored by a bare `cat` or `tee` while every other statement is a quiet command (cd, mkdir, chmod, ls, echo ...) with no substitution and nothing sets `PATH=` or another variable that changes what runs, else the single-quoted arguments of `inert-arguments.mjs`; a body a later statement runs or reads (`bash x.sh`, `xargs curl < f`, `source f`), inside `{ }`, a loop or an `if`, or next to `exec`/`coproc` is scanned whole.
- `outward.mjs` - push, gh release, gh pr merge and publish asks, and the merge and release verbs and `api` writes of glab, hub and tea.
- `inline-code.mjs` - interpreter code given on the command line (`-e`, `-c`, `--eval`, `php -r`, `deno eval`, also glued on: `-c"code"`); asks when it runs a command it builds from pieces, and for PowerShell `-EncodedCommand`.
- `output-trim.mjs` - the `updatedInput` rewrite of a plain test or build runner call: full log to a temp file, its path printed first and the last 150 lines after, the runner's exit code kept.
- `guard-fallback.mjs` - reads the hook input and gives the plain ask when the input is not hook JSON or the guard's own code failed.
- `timed-ask.mjs` - the timed native dialog (osascript / PowerShell popup / zenity with `--no-markup`; `timed-ask-async.mjs` runs it as a closable child for the question popups), 2 min by default (`CLAUDE_ASK_TIMEOUT_S`; a caller may pass its own `timeoutS`, as `permission-timed-allow.mjs` does with `CLAUDE_PERMISSION_TIMEOUT_S`), fallback to the native ask; `CLAUDE_GUARD_ASK=allow` allows a request at once unless it is marked `outward`. Shown values are masked first (with their real line breaks, before anything is flattened or cut), then put on one line (line breaks become a visible mark; control, format, bidi, zero-width and other default-ignorable characters are dropped) and cut to head + tail + length (a detail line may keep its start instead; its label is masked and cut too). On macOS the decline button is the cancel button, so Esc declines and never takes the default.
- `answered-commands.mjs` - hands a guard dialog's allow to `permission-timed-allow.mjs` (`~/.claude/state/guard-answered/<session>.json`, a 0700 per-user folder and 0600 file, links refused; sha256 of agent, directory and exact command; used once; window 10 s after the guard's answer), so one command never gets two dialogs. Any process of the same user can still write a record inside that window and skip one dialog for that exact command, except a command the guard classes as DESTRUCTIVE, which never uses the hand-over.
- `allowed-literals.mjs` - the folder of the old per-session memory of literal secrets allowed before owner decision R22-G1 (`~/.claude/state/guard-allowed/`, still protected by `guard-state-write.mjs`) and `MIN_VALUE_LENGTH`; nothing reads or writes that memory any more, since a secret no longer asks.
- `remembered-ask.mjs` - bounce once, else the timed ask (`askOrBounce`), and the one log line of a literal secret (`logSecretKind`: outcome `secret`, its kind, no command, no value).
- `loop-values.mjs` - the values of a plain `for` list, so its body is judged once per value: only items that are plain literal words, a name with one `for` header read only as `$NAME` or `${NAME}`, at most 64 combinations per line (`MAX_LOOP_READINGS`), filled in only between the header and its `done`; anything else keeps the run-time bounce.
- `docker-advice.mjs` - advice once for `docker rm` (also `podman`, `nerdctl`, `container rm`) without `-v`; the identical command sent again runs.
- `bounce-once.mjs` - the one-time bounce of a command the agent can rewrite, with its deny text (`~/.claude/state/guard-bounced/<session>.json`, hashes only); its `adviceOnce` also serves `agent-model-guard.mjs`; `reason-classes.mjs` - a fixed class name for every guard reason, so the bounce knows what it may bounce and names the rest without command text.
- `session-store.mjs` - the per-session store files of `bounce-once.mjs`: lstat-checked, never through a link, never waiting on a FIFO, cleanup of its own old files only.
- `session-lock.mjs` - `withSessionLock`, built on `session-store.mjs`: a lock file (`<pid> <token>`, removed only by its holder, taken over only from a gone pid after 0.5 s or from anyone after 5 s, one waiter at a time, behind a `<lock>.break` file that others treat as a busy lock; it is read again under that file and renamed aside only while it is still the stale one, else linked back; in a rare double release-and-take the moved lock can still be lost) lets hooks recording at the same moment take turns. A caller waits up to 1 s; one that must not wait (the status line's limit sample) passes `waitMs: 0` and tries once.
- `guard-log.mjs` - masked JSON-line decision log (`~/.claude/logs/guard.jsonl`, `CLAUDE_GUARD_LOG`; at 5 MB it moves to `guard.1.jsonl` under a lock and an empty log replaces it in one rename; file 0600, directory 0700; a link, FIFO or device at the log path is never followed, written or waited on).
- `plain-file.mjs` - the one safe open (no waiting, no link followed, regular files only, no append to a hard-linked file, a size cap) for the host list, the decision log and the edit log.
- `remote.mjs` - production-host list (a list file that is not a plain file makes every host ask) and the ssh/scp/rsync/psql/mysql write classifier; `sql.mjs` - statement-level read-only SQL check and host detection.
