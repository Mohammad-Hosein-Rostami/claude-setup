# Catalog

Everything this setup ships, read from the files in `home/`, `settings/`, `plugins/` and `tools/`. Skill and agent
descriptions are quoted from their frontmatter; those descriptions are what make them trigger.

## Agents (`home/agents/<name>.md`)

| Agent | Description (trigger) | Model |
| ----- | --------------------- | ----- |
| `architect` | Use for architecture, system/API design, trade-off decisions, ADRs and planning of non-trivial or cross-package work. Produces a compact spec for Sonnet to implement; never implements. Skip for small or obvious designs. | claude-opus-5-5 |
| `deep-debugger` | Use for hard bugs - when one honest fix attempt already failed, the failure is intermittent, spans packages, or the cause is unclear. Finds the root cause and proposes the minimal fix; does not rewrite code at length. | claude-opus-5-5 |
| `implementer` | Use to execute a clear spec or well-defined non-UI task - multi-file implementation, refactor, tests - when the main session should stay clean. For pages, components, layout or styling use `ui-implementer`. Takes a spec path or precise instructions and returns a short report. | sonnet |
| `ui-implementer` | Use instead of `implementer` for any UI work - pages, screens, steps, components, layout, styling, forms, dialogs (.tsx/.jsx/.vue/.css/.scss, MUI, Tailwind). Preloads the UI skills, implements the spec and runs the UI done-gate. Returns a short report. | sonnet |
| `reviewer` | Use after a change (including a DB migration) to review it for correctness, regressions, security and rule violations. Read-only; returns a prioritised, rule-id keyed findings list. | sonnet |
| `runner` | Use to run tests, lint, typecheck, build or any noisy command and get back only the verdict and failures. Keeps verbose output out of the main context. Does not edit files. | haiku |
| `scout` | Use for read-only lookups - find where something is defined or used, list files, read several files and summarise, check how a pattern is done. Cheap and fast; returns a short answer, never raw dumps. | haiku |
| `security-auditor` | Use to audit a diff or feature for security issues, especially auth, input handling, secrets, uploads and agent tools reading untrusted text. Read-only. | opus |
| `test-writer` | Use to write tests from a spec or acceptance criteria before or without reading the implementation, so tests do not confirm the code's own mistakes. | sonnet |
| `visual-qa` | Use to check a built UI against its Figma baseline and at several widths with ui-check (compare, responsive), optionally fixing failures. Returns a short verdict, never images. | sonnet |

Routing policy (which tier does what) is in `home/modes/_lead.md` (injected into the lead session by `mode.mjs`): the Opus session leads and delegates. `general-purpose` (no `model`) runs on Sonnet 5.5 via `env.CLAUDE_CODE_SUBAGENT_MODEL`; the built-in Explore agent gets `sonnet` and Plan (every mode) `opus` from `agent-model-guard.mjs`, otherwise they run on the lead's model; precedence is the Agent call's `model`, then frontmatter, then that env var.
`architect`, `reviewer` and `security-auditor` have `memory: user` (notes in `~/.claude/agent-memory/<name>/`); `reviewer` and `security-auditor` stay read-only for project files through the `agent-memory-only.mjs` hook in their frontmatter.

## Hooks (`home/hooks/`, wired in `settings/base.json`)

| File | Event | What it does |
| ---- | ----- | ------------ |
| `pre-bash-guard.mjs` | PreToolUse(Bash) | Blocks nothing for good. A command with a hit that a rewrite fixes (a variable command word, a risky word inside shell expansion, a literal secret) is first bounced back once with the fix (a deny the agent reads, outcome `bounce`); the bounce also names every other reason that will still ask after the rewrite, and the identical command sent again gets the dialog. Otherwise a rule hit (git `--no-verify`, force push incl. `+refspec`, `rm -rf` outside the project, disk wipes, literal secrets, `git push`, `gh release`, `gh pr merge`, package publish, writes to production hosts from `~/.claude/private/prod-hosts`) opens a timed dialog: Allow by default, no answer in 2 min (max 190) goes ahead, Deny on click; Allow and timeout print no decision (normal permission flow and deny rules still apply); no GUI or a failed dialog falls back to the CLI prompt. Quality rules (a hand-edited lockfile, a `git merge` or `git pull` that can create a merge commit, a branch moved by plumbing: `git update-ref refs/heads/<x>` or `HEAD`, a ref in a variable, `update-ref --stdin` setting anything but a literal ref outside refs/heads/ (HEAD, `%s`, `$REF` count), `branch -f`, `push|fetch . a:<branch>`, `fetch -u <any repository> a:<branch>`; `update-ref -d` and literal refs outside refs/heads/ stay silent; git itself already refuses `branch -f` and a plain `fetch|push .` onto a branch checked out in any worktree) get advice instead: denied once with the fix, the identical command sent again runs, no dialog. Every git global option is read, so none can hide a guarded subcommand. Commands git itself runs (`lib/git-runs.mjs`: `rebase -x`, `bisect run`, `submodule foreach`, `-c core.pager=`, clone's `-c`, `git config` writes, `alias.*`, `GIT_SSH_COMMAND` and the other variables git runs, `ext::` and `git remote-ext`) get the same rules as a `bash -c` body; what git runs that the guard cannot read asks "git runs a command this guard cannot read" (a `--config-env` variable not set in the line, `ext::` switched on, and, next to a dangerous word, config files or values set through `printf -v` or other variables). Git's own programs (`git-push`, `<exec path>/git-rebase`) count as `git <sub>`, `git config` values after `--` are read, and the value of a variable git runs is checked wherever the line assigns it (`lib/git-run-values.mjs`; one it cannot read, such as `$(...)`, asks the same unless it is one reference like `"$EDITOR"`). Command names ignore case on macOS and Windows, as their file systems do; a variable assigned from a backtick is unknown, as after `$(...)`. Destructive hits say `DESTRUCTIVE:`. Logs decisions to `~/.claude/logs/guard.jsonl` and code files written through `sed -i`/heredocs for the typecheck gate. Scans every word of a command for these rules (so `ionice -c3 rm -rf /x` and `$'\x72m'` are caught); `eval` of a variable or substitution asks. A second character-level parser (`lib/shell-lexer.mjs`) is a raw-text backstop, and a fail-to-ask rule (`lib/raw-risk.mjs`) asks whenever a hidden-execution construct (`$(`, backtick, `<<`, `<(`, `eval`, `trap`, `case`) meets a dangerous word anywhere in the raw text (a commit message and the single-quoted argument of echo, printf, grep, rg, jq, sed without `e`/`w`/`-i` or `git log` without `--output` are data, `lib/inert-arguments.mjs`; data piped to a shell, a file writer or out of a group, a line that writes any file, a `$'...'` word, `${`, `case`, `eval`, a function or `PATH=` still asks); a command over 32 KB asks "command too long to check"; `| bash`, `bash <<EOF`, a variable command word, `env -S`, `su -c`, `git -c alias.*`, `gh api` writes and `diskutil erase` ask. Anything it cannot parse is allowed. Unquoted brace words are expanded as bash does and a split unquoted variable is judged word by word; a look-alike command name or a brace word it cannot list asks. It is a tripwire, not a sandbox (README Limits). |
| `lib/git-advice.mjs` (used by `pre-bash-guard.mjs`) | PreToolUse(Bash) | Advice, never an ask: denied once with the fix, the identical retry runs. Four rules in one call: a merge that can create a merge commit, a branch moved by plumbing, creating a copy of an existing lane branch (`checkout -b`, `switch -c`, `branch`, `worktree add -b` of `<name>-<n>`, `-fix`, `-fixes`, `-v<n>` or `-redo` while `<name>` exists: continue the same branch), and `git merge --ff-only <ref>` on main, master or develop with no full-suite PASS at that commit (land with `git-tidy land`). The two repository rules ask git (hardened: no hooks, fsmonitor or embedded bare repository; one 2 s budget for all calls of a command line) and the `test-pass` tool; an error, a timeout, a folder it cannot read (`cd "$X"`, `pushd`) or a missing tool gives no advice. |

MCP, Agent, ExitPlanMode plan approval, protected files; any mode; interactive, background and `-p`) gets the timed dialog, going ahead after 2 min (`CLAUDE_PERMISSION_TIMEOUT_S`); Deny (Esc on macOS) blocks; no GUI leaves Claude Code's own prompt. | `post-edit.mjs`, `typecheck-gate.mjs` | PostToolUse(Edit, Write, MultiEdit); Stop, SubagentStop (gate) | Runs the project's own format and lint scripts (only those present in the nearest `package.json`) on the edited file and logs the file for `typecheck-gate.mjs`. A script that targets the whole repo (`prettier --write .`, `eslint .`) is replaced by the tool's binary on the edited file. A lint failure about the file ends the run at once. | `commit-gate.mjs` | Stop, SubagentStop (gate); PostToolUse(Edit, Write, MultiEdit, NotebookEdit); PreToolUse (all tools) | Records each file the session or one of its agents changes with those tools (`lib/own-edits.mjs`), and at the first tool call of the session or agent which files of its worktree are already dirty and how (path + content hash, `lib/dirty-baseline.mjs`), and blocks a stop once per dirty state (agent + worktree + hash of those files' `git status --porcelain` entries) when recorded files are modified, staged or untracked non-ignored files in the session's own worktree (the one holding `CLAUDE_PROJECT_DIR`; for a subagent, the one it started in; never a folder it only cd'd into); a subagent counts its own files, the lead every file of the session; files a Bash command made or changed since that first call count too (dirty now, clean or different at the baseline); dirt from before it, another session's recorded files and, for an agent, another agent's recorded files never block: commit them as small Conventional Commits or say why they stay. git runs hardened (fsmonitor off, no bare-repo discovery, no hooks) and a repo whose own config defines a filter is passed: no program from the repository runs.
