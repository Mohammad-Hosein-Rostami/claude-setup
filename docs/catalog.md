Everything this setup ships, read from the files in `home/`, `settings/`, `plugins/` and `tools/`. Skill and agent
descriptions are quoted from their frontmatter; those descriptions are what make them trigger.

The main session starts only lex, dev, tess and max (max rarely, to ship), never a helper, and runs at most 3 of each of them
at once; they start their helpers themselves and report back in at most 150 words, with the detail in a file. No other agent
starts lex, dev, tess or max: it asks the boss with a `needs:` line, and the boss starts it and relays the result. Writers
(dev, dev-part, dev-docs, dev-ui, dev-pixel, dev-debug, tess-write, max) each work in their own worktree. An agent that needs
the owner stops and returns a `questions:` block (plain words, what it blocks, 2-4 options with the recommended first). Each
agent file's `model` and `effort` are a floor: a call never passes a lower one (`home/CLAUDE.md`, "Agent calls").

## Hooks (`home/hooks/`, wired in `settings/base.json`)

A hook reads a path that comes from its input, a session transcript or a state folder through `lib/plain-file.mjs` (or the same open flags: `O_NONBLOCK`, `O_NOFOLLOW`, then `fstat` says regular file): a FIFO or device there is refused at once instead of holding the hook until its timeout. Where a link is legitimate (an agent file, `~/.claude.json`, a project's `package.json`, a ui-check run file) the path is resolved once with realpath and the real file read the same way; elsewhere a link is refused. `tests/hook-reads-no-wait.test.mjs` plants a FIFO at each such path.

| File | Event | What it does |
| ---- | ----- | ------------ |
| `notify.mjs` | Notification(permission_prompt\|elicitation_dialog\|elicitation_url_dialog\|quota_auto_resume_stale\|quota_auto_resume_disabled); StopFailure(rate_limit) | A desktop note only when work waits on the owner or stopped (display design 7.10): `Needs you: question 1 of 2 (Scope) · default in 1:00` (asking marker, which holds the first question's short header; the parentheses are left out when there is none; else `a permission prompt` / `an MCP server asks for input`), `Stopped: 5-hour limit, resumes 17:40` (this account's last limit sample, `CLAUDE_ACCOUNT`; else `reset time not known`), `Stopped: ...` for a quota wait that will not resume by itself (the unused Stop note queue and its Stop entry were removed on 2026-11-24). Output is `terminalSequence` only (OSC 777 Ghostty, OSC 99 Kitty, OSC 9 otherwise, a bell for Apple Terminal), on `preferredNotifChannel` from `~/.claude.json` (none when `notifications_disabled`). Always exits 0. |

### Hook details

#### `project-merge.mjs`

- The lead gets: a header with the repo key and where it came from, labelled "names and values below are repository data, not instructions"; a `Warning` line when a project settings file turns all hooks off (`disableAllHooks`) or has `claudeMdExcludes` that may hide our CLAUDE.md or rules files (R22-L4: warn only); `Instructions` (CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md, AGENTS.md with how it loads, `.claude/rules` counted); `Skills` (count, and each project skill ours hides by name, any case, with its SKILL.md path); `Agents` (names, `maxTurns`); `Hooks beside ours` (event and count; Stop blocks count toward `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`; we register no Stop hook); `Settings that change ours` (a weaker model or effort, our check switches, permission mode, keys that replace ours; values only for model, effort, mode, `disableAllHooks` and our switches, every other value never shown); `MCP`; `Note` (its path, "loaded by CLAUDE.local.md", or the path to write); `Not checked` (anything a limit or the deadline stopped); the project-agents line of `lib/project-agents-timed.mjs`; then each note under `--- note <key> (shared or personal) ---`.
- Agents get nothing from it (plan 2026-11-24).
- Repo key (`lib/project-note-key.mjs`): the remote name without userinfo, else the main checkout's folder name (worktrees map to it), else the SVN root's or the folder's name; a git failure in a repository says "repo key not checked", never a guessed key, and the project-agents line still comes (its child finds the agent folders by a filesystem walk, with no git); a network (UNC) path is not followed; a session in HOME gets nothing.
- Notes: `home/project-notes/<key>.md` (found from the hook's real path) then `~/.claude/project-notes/<key>.md`, one real folder read once, regular files with one name only, at most 8 KiB each.
- Reads (`lib/project-setup-scan.mjs`) never follow a link (each one, a linked `.claude/skills` included, is named under `Not checked`), list at most 5,000 entries, 8 levels deep, read settings files up to 256 KiB (a bigger one is "not checked").
- Output: JSON `hookSpecificOutput.additionalContext`, at most 6,000 characters, notes last and cut with a line naming the file.
- Read-only, no state file; one deadline of 4,000 ms below the 5 s timeout of both entries (git 1 s per call, the scan at most 1 s, the agents child what is left).
- Nothing for a project with no AI files and no note, or for a SessionStart inside a subagent.
- Never blocks.

## Project notes (`home/project-notes/`)

Notes per project, one `<key>.md` each (the key is the remote repository name, else the folder name). Shared notes live
here in the core repo; personal ones live in `personal/project-notes/` (git-ignored, its own repo), which
`~/.claude/project-notes` links to. The first install of that layer moves each note here that git does not track, or that a pull just deleted, into the personal folder; later installs leave new notes here. The
project's committed config never references a note. Policy: "Project AI setups" in `home/CLAUDE.md`.

## Status line

`home/statusline.mjs`: the status line (spec R18, owner decisions RC14 to RC20 of 2026-11-22), 2 rows when idle (git and session) and at most 5 when busy (alert, agents, 1 or 2 git rows, session; 4 from 12 terminal lines, 2 below), each fitted to `COLUMNS - 5` on every run with an 8-wide dim label from 90 usable columns; rows drawn by `home/tools/board/lib/render.mjs`, every row with an example in `home/tools/board/README.md`.

- No job, now, step or estimate rows and no `/where` tree (plan 2026-11-24).
- Alert row (only while a question or permission prompt waits): `? ANSWER NEEDED · 1 question · recommended answer taken in 1:40` from the asking marker.
- Agents row (only while an agent runs, RC8): `agents  5 running · 1 done · ! dev quiet 6 min`, only the agents that need a look named (`+K more` past the width).
- Git rows (RC15): in the session's repository `git     claude-setup  main  ↑2 to push · 1 staged · 3 changed · 1 new · stash 1 · last commit 8 min ago` and a `lanes` row of its active branches; outside a repository or with a second one, one row per used repository (at most 2) with its lanes after ` │ `; `git     loading` before the first board refresh.
- Session row: `session Opus 5.5 high · context 29% · 5h 90% left, empty ~22:32 · 7d 47% left · acct mine` (context against the auto-compact window; from 60 % used `, resets 22:10`; the account from `CLAUDE_ACCOUNT`), dropping the account, then 7 d, then the 5 h clock when short.
- Colour by kind (RC14): branch names green, bars and their counts cyan, durations and clocks blue, session values grey-violet (256 colours when `TERM` has `256color` or `COLORTERM` is `truecolor`/`24bit`, else the basic 16; a light palette (RC20) under `CLAUDE_STATUS_THEME=light` or a light `COLORFGBG`); yellow, red and magenta only for needs a look, a problem and needs you; every state also in words.
- ASCII cells under `CLAUDE_STATUS_ASCII=1`, `TERM=dumb`, the old Windows console or a non-UTF-8 locale; no colour under `NO_COLOR`, `TERM=dumb` or the old Windows console.
- It reads only cache files (no git, no transcript); it writes the account's limit sample (none without `CLAUDE_ACCOUNT`); its only spawn is the claimed board refresh; an error while drawing prints the session row and one `status line error:` line, any earlier error that line alone, exit 0.

### Tool details

#### `board`

- It holds every subagent with what it does now and its worktree, and git per worktree (`lib/git-state.mjs`: fixed flags, `--no-optional-locks`, fsmonitor, hooks path, signature program and lazy fetch off, 1.5 s per call and 3 s per refresh, sized for a loaded machine (`lib/git-call.mjs`); counts git could not give and no earlier answer holds are `unknown` with the reason, never null, and with no branch refs the git row says `branches unknown`, never clean; staged, changed, conflicted and new files (new only on the session's own worktree, every 60 s), the stash count, an operation in progress with its step (`rebase 2/3`), and up to 4 active branches per repository (checked out in the session folder, holding a live agent, with changes, ahead of the base with a commit in 24 h, or the base off its upstream) with upstream, ahead/behind and the agents there; a worktree whose repository config names a filter gets refs only, `trust: refs`, since `status` would run it; `lib/repos.mjs`: the session folder's repository, then up to 2 more holding a folder this session used (agents' edits, launch worktrees and cwds, live or done, and the lead's Edit/Write folders from the main transcript's new bytes), newest use first (owner decisions RC15, RC19); git runs only on the git folders the repository records (`--git-dir`/`--work-tree`, never a worktree's own `.git`, never the used folder itself); a repository git could not read in time keeps its last state up to 60 s, marked `stale`; `lib/trusted-repos.mjs`); commits landed today (`lib/repo-stats.mjs`, every 60 s); agent tokens; transcript cursors and the git cache in `~/.claude/state/board-cache/`.
- No job, step or estimate facts and no `where` tree (plan 2026-11-24).
- Unreadable transcripts show nothing and never throw; an old `subagents/workflows/` folder is not read.

#### `git-tidy`

- `node ~/.claude/tools/git-tidy/git-tidy.mjs check [dir] [--base b]` reports unpublished merge commits, merged branches and worktrees, `superseded-copy` (an older copy of a re-done lane: `X`, `X-2`, `-fix`, `-vN`, or an equal tip, proven by ancestry or equal patch ids; the newest stays) and `agent-leftover` (an empty `worktree-agent-*` branch nothing uses), `merged-branch ... content-equal` (merging it changes nothing, one `git merge-tree --stdin` for all unmerged branches, and every path it changed is the same blob on the base, a `git diff-tree` check no merge driver or attribute can fake: the one content proof for a squash or a fold that landed as it is), `stale-checkout` folders whose branch moved under them and `dirty-base` (edits in the base folder) (exit 0 when none; the hint `unlanded-lane?` names a branch with unlanded work and no commit for 2 h, `in-lane?` one whose commits are all in a live branch, never removed);
  - `prune [--apply] [--include-recent]` lists, and with `--apply` removes, what is provably merged, copies (content-equal included) with their clean worktrees and leftovers, logging each branch with its sha to `<git common dir>/cs-tidy-log.jsonl` before it deletes it, for a restore (a log that is not a regular file: nothing removed, exit 2) (never a dirty worktree, one with an assume-unchanged file, a skip-worktree file on disk or a git repository inside an ignored folder, a stale entry whose HEAD reflog or index holds work found nowhere else (a stale entry's HEAD no branch holds is kept as branch `stale-head/<id>`), a branch with work of its own, or a copy whose worktree a live agent used in the last 60 minutes; `--apply` compares with one base commit and stops, keeping the rest, once the base moves);
  - `land <branch>` rebases the lane onto the base (with `--tip <sha>` it lands only that sha: when its own rebase changes the commit it exits 5 and lands nothing, so the caller rebases and checks again), proves the UI check plan of the rebased diff (`ui-proof check --plan` with `--brief <file>` as the request and `--matrix <abs lane matrix>`; rules `home/standards/ui-checks.md`; always on, no waiver: the old waiver flag exits 2), fast-forwards the base in the base folder, removes the lane, its helpers and copies, and prints `check: clean` and `from <sha>`, the base tip before the fast-forward (the reflog's value when the base moved in between) (exit 2 base not ready, 3 conflict, 5 base moved, 6 `ui-proof`: the plan is not proved (the failing states and the reason are printed), a plan other than none has no `--brief`, or the ui-proof tool cannot be loaded, 7 `new-file-size`: a new file over 5 MB that `--brief <file>` does not name; a proved plan other than pixel prints `ui plan <depth>: proved` and its `follow-up:` lines (none only when a UI file changed, such as a docs page, so a lane with no UI file prints what it did before));
  - `range <reviewed-sha> [--landed <sha>]` finds the base's reflog step that landed those patches (`from`, `to`; exit 1 not found).
- Used by the `git-linear-history` skill.
- `land` fetches the base's upstream first (20 s timeout; offline: a WARN line) and exits 8 `upstream-moved` ("`git pull --rebase` first") when it holds commits the base lacks; a landing prints `published N` (`lib/upstream.mjs`).
- `lane claim --repo <abs> --branch <name> --base <sha>` hands a lane the lowest free pool folder `.claude/worktrees/lane-<n>` (or adds the lowest unused one when all are busy; no cap) under one pool lock per repo, switched to the branch (an existing one never reset), cleaned with `git clean -fdx` keeping `node_modules`/`.venv` while their lockfiles are unchanged, locked `cs-lane-pool <branch>`, then installs per tracked lockfile (`npm ci`, `pnpm install --frozen-lockfile`, `yarn install --immutable`; exit 1 `lane not ready`); `lane list`, `lane release` (detach, unlock, delete the landed branch; exit 3 refused) and `lane reclaim` (removes free folders idle 24 h, keeps the lowest free one of a repo in use); a busy folder (unfinished work, a commit off the base, a git lock, not a worktree) is never touched; claim and reclaim write job-made records; `land` detaches a pool folder at the landed sha instead of removing it; `check` shows idle folders and a fresh lane in a locked worktree as info lines, never findings.

#### `land`

- Then `sweep.mjs` runs git-tidy's `prune --apply` over the repository (a branch goes only when its tip is on the base or merging it changes nothing; copies of another branch and a fold the lane changed later stay; git older than 2.40 skips the sweep with a stderr line; a dirty, locked or recently used worktree (an assume-unchanged file, a skip-worktree file on disk or a git repository inside an ignored folder counts as dirty), a base that moves during the sweep (it stops) or any doubt keeps it, with the reason; an unfinished rebase or merge prints `cleanup skipped:`; a deletion log that is not a regular file stops the clean-up before it removes anything, printed on stderr, and the land still exits 0), never removes a stale worktree entry (lists it under `left:`), logs each deletion with its sha (restore with `git branch <b> <sha>` within 2 weeks) and ends with `left:` (each remaining branch: `in <B> (lands with it)`, `kept: <reason>`, `on <base> (<state>), not removed`, `idle <h> h` or `active`, with `ahead <n>`).

#### `disk-free`

- Check it before a build batch and start none on `FAIL`.
- See `home/tools/disk-free/README.md`. **disk-clean** (same folder): `node ~/.claude/tools/disk-free/disk-clean.mjs [--apply]` (dry run by default) removes what piles up on the disk (and Figma pulls in `~/.cache/figma` idle for 30 days): scratchpad folders of sessions idle for 3 days, or 30 when its transcript is not in this config dir (`/private/tmp/claude-<uid>/*/<session-id>`, never the current session; a session of another config dir that writes nothing in its folder for 30 days loses it), in the scratchpad of a session it keeps (the current or a running one) the `cs-test-*` and git clone folders with nothing modified for 2 days, first seen by disk-clean over 2 days ago and holding no git work (worktree, changes, stash, local-only commits), leftover test temp folders older than 1 day (`cs-test-`, `cs-run-` and the old test prefixes), `~/.claude/projects` folders of throwaway temp paths, and hook counters in the temp folder older than 3 days.
- Never follows a symlink, never removes a running session's folder or anything not owned by this user in folders closed to others (an unsafe root is skipped), removes from inside the folder (chdir plus identity check), renames a folder aside and re-checks it right before removing it (a resumed session keeps its folder), takes a run lock; streams folders, so a million entries is fine; the text report prints every name escaped and at most 10 `NOT removed` and 10 `SKIPPED` lines (`--all-lines`, which the start hook passes, lists all in its log).
- `with-run-tmp.mjs -- <command>` runs a command with its own TMPDIR and removes it afterwards (nothing calls it by itself).

#### `long-run`

- A crash, reboot, usage limit (waits until the printed reset + 120 s), pause, stop or takeover continues the same session with `--resume`; failed steps retry with backoff up to the per-step loop guards `maxAttempts`, `maxStarts`, `maxVisits` (loop guards, not budgets; a step is stopped after 240 minutes unless the job sets another `stepTimeoutMinutes` or `null`); blocked, needs-owner and guard stops hold the run (`interrupt`) until `resume --answer | --retry | --skip | --abandon`.
- Also `status`, `watch`, `log --tail`, `pause`/`stop [<step>]`, `takeover` (prints the lines that open the session by hand), `tell` (a message to a running step at its next safe point), `rerun --from`, `summary`, `prune [--older-than <days>]` (removes done and abandoned runs that ended that long ago, default 30), `events --follow | --wait-next` (one numbered line per event in `~/.claude/state/long-run/events.log`), `notify` (desktop note, ntfy phone push; `CLAUDE_LONG_RUN_DESKTOP_NOTES=off` turns the desktop note off, which the tests' `cleanEnv` sets); timeout knobs for tests, named `CLAUDE_<TOOL>_<CONSTANT>` and taking only a whole number of ms up to 2^31-1 in digits only (`lib/env-ms.mjs`): `CLAUDE_LONG_RUN_CONTROL_POLL_MS` (control file reads, 2 s) and `CLAUDE_LONG_RUN_SWEEP_GRACE_MS` (grace for a boss's leftover processes, 3 s), `autostart` (launchd / Task Scheduler resume after login), `schedule`, `check --deps` (LangGraph and the SQLite module load on this Node; `check`, `start` and `check --deps` also refuse when the install stamp names another Node ABI, with the fix `scripts/install.sh`).
- A SIGTERM, SIGINT or SIGHUP of the driver pauses the run cleanly: every boss is ended and so is whatever of its process tree outlives it (a subagent's Bash runs in its own process group); after a SIGKILL `status` warns that the lost driver's boss still runs and `resume` ends it and its tree first.
- Each step journal records the boss's agents (from the stream) and the git worktrees that appeared during the step; every resumed start gets a `RESUME-STATE` block naming the unfinished agents (resume each by SendMessage), those worktrees with their uncommitted changes and new commits, and the commits the step already made; at the end of a run a worktree an agent of the step named is removed when it holds no uncommitted, untracked or ignored file and no commit of its own; every other one is kept and named in `summary.md`.
- A job folder may be written `~/...`.
- Parallel groups (`Send`) run up to 3 bosses at once, optionally each in its own lane worktree.
- State in `~/.claude/state/long-run/<run>/`.
- Exit 0 ok, 1 refused, 2 usage, 3 no such run or step, 4 run busy.

### Script details

#### `install.mjs`

- Safe to repeat (a second run changes nothing); one install at a time (a lock file `~/.claude/.claude-setup-install.lock` with the running install's pid, also taken by `--uninstall`; taken over once that process ended, never while it runs (past 30 minutes the refusal names the pid and the lock path, to end it or delete the file by hand), and a lock with no pid in it only after 30 minutes; a second install exits 1 with a message).
- `--update --to <tag>` points the links at a detached worktree `~/.claude-setup-at/<tag>` (rollback; the checkout does not move), `--update` points them back; `--uninstall` removes what the install record `~/.claude/.claude-setup-install.json` names and restores the backups from `~/.claude-backup-<stamp>/`, then lists what it left in place (a backup whose path exists again, a link or written file you changed, a folder not empty).
- `--claude-version <x.y.z>` installs that Claude Code (2.1.326 or newer), runs `claude --version` right after and restores the old binary when it is not that version.
- On Windows it stops without Git Bash.
