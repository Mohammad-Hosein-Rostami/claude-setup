# Troubleshooting

| Symptom | Cause and fix |
| ------- | ------------- |
| `doctor.sh`: `link X` FAIL | `~/.claude/X` is not the repo symlink. Run `scripts/install.sh`; the old item is in `~/.claude-backup-<stamp>/`. |
| `doctor.sh`: `FAIL disk free ...` (or a landing refused with it) | Less than 5 GB free (`DISK_FAIL_FREE_GB`; `WARN` below 15 GB, `DISK_WARN_FREE_GB`). Clear the caches the line names, biggest first (Xcode DerivedData, CoreSimulator, `~/Library/Caches`, npm/pnpm stores, `docker builder prune`, old `/private/tmp/claude-<uid>` session folders), then re-run. |
| `doctor.sh`: settings differ | Live edits (`/config`). Copy wanted keys into `settings/*.json`, re-run the installer. |
| A change does not show in a session | The session started before it. Restart it (`/exit`, `claude -c`); after a `settings/` change re-run the installer first. |
| A hook never fires | Test it as Claude runs it: pipe the event JSON Claude sends into the script (`echo '<event json>' \| node ~/.claude/hooks/<name>.mjs`). A hook that should print and prints nothing did not run `main()`: the entry check must compare `realpathSync(process.argv[1])`, because `~/.claude/hooks` is a symlink and `import.meta.url` is the resolved path. |
| Sessions ended when the editor window closed or reloaded | They ran in the editor's built-in terminal, which stops with the window. Run long or unattended sessions in a plain terminal app or tmux; resume with `claude --model <m> --effort <e> -c`. |
| Windows: items copied, edits do not follow | Symlinks need Developer Mode. Enable it and re-run `install.ps1`. |
| Plugin install skipped | `claude plugin` subcommands missing. Use `/plugin` and install the plugins the install output names (the ones `enabledPlugins` turns on). |
| Commit rejected, gitleaks | A staged change looks like a secret. Remove it; do not bypass the hook. |
| Commit blocked: gitleaks not installed | `brew bundle --file tools/Brewfile` (or the Windows script). |
| `ui-check` exit 2: `Playwright not found from ...` | Pass `--project <dir with @playwright/test>`. |
| `ui-check` exit 2: `cannot launch Chromium` | `npx playwright install chromium` in that project (the tool never downloads browsers). |
| `ui-check` exit 2: `odiff-bin is not installed` | `scripts/install.sh` (or `pnpm install` / `npm install` in `home/tools/ui-check`). |
| `ui-check` exit 2: `FIGMA_TOKEN is not set` | See `docs/setup.md`, or fill the cache with the MCP fallback. |
| `figma-pull` 403/404 | Token lacks access to the file, or the node id is wrong (`12:34`, colon not dash, in the command). |
| `compare` size mismatch | Page root is not the frame size. Fix the root element's size first; padding is applied only so the diff still runs. |
| `compare` diff high, element table empty | Wrong root, different content, or a font fallback. Check `actual.png` once; set up the same state as the frame. |
| `compare` differs between runs | Page animates or loads late data. Mock the data; the tool already freezes animations and waits for fonts and images. |
| `line-height: normal` row | Set an explicit line-height equal to the Figma value. |
| `responsive` reports a tap target you cannot change | Inline links in text are exempt (the tool skips `display: inline`); otherwise grow the hit area with padding. |
| Dialog or prompt from a Bash command | `pre-bash-guard.mjs` asks for `--no-verify`, force push, `rm -rf` outside the project, push, publish and prod-host writes, plus commands that hide what runs (`| bash`, `$VAR` as the command, `env -S`); write the command out to avoid the dialog. A literal secret (a test password) asks nothing: the log names its kind (owner decision R22-G1). The first time, a `$VAR` command word, a risky word inside shell expansion or a word or arithmetic known only at run time (`read X; git $X`, `$(( $(cat n) + 1 ))`; a plain `for d in a b` list is judged per value and does not count) is sent back to Claude with the fix instead of a dialog ("Not run: the guard bounced this command once"); sent again unchanged, it asks. A hand-edited lockfile, a merge that can create a merge commit or a `docker rm` without `-v` is denied once with advice and no dialog; the same command sent again runs. "risky word inside shell expansion" means a `$(...)`, backtick, heredoc, `eval`, `trap` or similar sits next to a word such as `git push` or `rm -rf`, whatever the quoting: move the risky command out of the expansion to avoid it (commit and PR message text, and a heredoc read by `cat`/`tee`, are plain data and do not ask); "command too long to check" is any command over 32 KB; "guard error: <Class>" means the rules themselves failed on this command (the command is shown in the dialog, the log keeps only the error class), please report it. Allow is the default; Allow or a real timeout (2 min, at most 190) prints no decision, so the CLI's normal permission flow and your deny rules still apply; only Deny blocks. Over ssh or without a display the CLI prompt appears instead. Decisions are in `~/.claude/logs/guard.jsonl`. |
| Known limit: a background job sends Return to the dialog | A job that types Return (or any key) into the focused window can press the dialog's default button, which is Allow. The guard cannot tell a real click from a keypress, so an unattended run with a background key-sender may auto-allow. Out of scope; stop such jobs while a run needs the guard. |
